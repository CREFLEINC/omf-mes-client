화면 구성 규범(`docs/screen-composition.md`)과 작업 절차(`screen-composition-procedure.md` 2장)에 따른 구성안이다.
설계 기준: `design/wiki/screens/01/W-01-10-정상품입하처리.md` (커밋 `cd15828d`).

## 유형

| 항목 | 내용 |
| --- | --- |
| 유형 | **T-W-C 처리형** |
| 근거 | 대상(입하 전표 → 입하 라인) 선택 후 입고 창고·적치 위치·입고 조건 입력, 확정 확인, 입고 확정 (스펙 §0 핵심 액션, §5-2, §5-4). 규범 1장 질문 2에서 처음 「예」 |

| 스펙과의 차이 | 스펙 §3은 좌우 2단(확정 대기 큐 + 확정 폼). 처리형 분리와 달라 설계 요청서를 남겼다(`.client-dev/requests/W-01-10-layout.md`) |

## 처리 화면

| 항목 | 내용 |
| --- | --- |
| 영역(위→아래) | 처리 머리 → 단계 표시 → 지난 단계 요약 → 단계 본문 → 하단 동작 바 |
| 처리 머리 | [← 정상품 입하 처리], 제목 = 입하번호, 요약 = 공급사 · 입하일시 · 거래명세서번호 |
| 선택 후 이동 | 다음 단계 (C-2) |
| 단계 1 「라인 선택」 | 입하 라인 표(행 전체 클릭으로 한 줄 선택). 자재 LOT이 없거나 수량이 0 이하인 줄은 고를 수 없고 사유를 칸 안에 보인다 |
| 단계 2 「입고 정보」 | 입고 창고*, 적치 위치*, 입고 유형*, 품질 상태*, 재고 상태*, 입고 일시*(날짜 `DatePicker` + 시각). 「추가 입력(선택)」: 사유, 비고 |
| 단계 3 「확정 확인」 | 입고 대상·입고 위치·입고 조건 요약, 「입고 처리 시 반영 사항」, 되돌릴 수 없다는 안내 |
| 주 동작 | 하단 동작 바 오른쪽. 단계 1 [다음: 입고 정보], 단계 2 [다음: 확정 확인], 단계 3 [입고 처리], 완료 [다음 라인 처리] |
| 보조 동작 | 단계 2·3 [이전], 완료 [정상품 입하 처리로] |

| 단계 | 경우 | 문구 |

| 1 | 라인을 고르지 않음 | 입고할 입하 라인을 고르세요. |

| 2 | 창고 없음 | 입고 창고를 고르세요. |
| 2 | 위치 없음 | 적치 위치를 고르세요. |
| 2 | 필수 코드 없음 | 입고 유형·품질 상태·재고 상태를 고르세요. |
| 2 | 입고 일시 없음 | 입고 일시를 넣으세요. |
| 3 | (비활성 아님) | 내용을 확인한 뒤 입고 처리를 누르세요. |

### 읽기 전용 값

| 값 | 출처 |
| --- | --- |
| 공장 | 입하 전표의 공장 |
| 입고 수량·품목·단위·자재 LOT | 고른 입하 라인(전량 입고, 스펙 §8-6 기본값) |
| 원천 문서 유형 | 입하 전표(`INBOUND_RECEIPT`, 이 화면의 원천은 늘 입하 전표) |
| 영업일 | 입고 일시의 날짜 |

**확인 필요**: 스펙 §4는 입고 유형·품질 상태·재고 상태·입고 일시를 「자동」으로 둔다. 규범 T-W-C도 업무 규칙에서 정해지는
값은 읽기 전용으로 두라고 한다. 그러나 이 값을 정하는 규칙이 스펙에서 미결이다(§8-3 품질·재고 상태 조합, §8-8 상태 출발값)
이고 입고 유형·입고 일시의 자동값 규칙도 명시돼 있지 않다. 기존 구현은 네 값을 사람이 고르게 했다.
추측으로 채우지 않기 위해 **입력 칸으로 유지**하고 화면 머리 주석에 이탈로 적었다.

### 숨길 기능

| 기능 | 이유 |
| --- | --- |
| 페이지 머리 「처리 대기 N건」 | 목록 계약에 처리 대기 건수가 없다 |
| 조회 조건 「처리 대기만」 기본 켬 | 목록 계약에 그 조건이 없고, 상태 코드 값 목록이 미확정이다 |
| 조회 조건 「상태」 | 값 목록이 비어 늘 고를 수 없다(C-4) |
| 목록 열 「처리 대기 수량/건수」 | 목록 응답에 라인 수가 없다. 행마다 라인을 부르면 요청이 행 수만큼 는다 |
| 「원천 문서 보기」 | 늘 비활성이던 버튼(C-4) |
| 「추천 적용」(적치 위치) | 스펙에 추천 규칙이 없다 |

### 반영 사항 (「입고 처리 시 반영 사항」)

1. 입고 전표 생성
2. 자재 LOT 상태 변경
3. 수불 원장 기록
4. 재고 가용 수량 반영
5. ERP G/R 송신 대기열 적재 — 즉시 전송 아님

한도승인 건은 5가 빠져야 한다(스펙 §5-5). 처리 전에 한도승인 여부를 알 수 있는 값이 입하 라인 응답에 없어
**확인 필요**로 남긴다. `EffectList`는 제외 표시를 지원하고, 화면은 지금 제외 조건을 넘기지 않는다.
처리 뒤에는 응답의 `erpMessageQueued`로 결과 요약이 실제 적재 여부를 말한다.
