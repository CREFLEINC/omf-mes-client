# PM95 시험 키트 — 모바일 화면을 손으로 돌려 보는 절차

**v3** · 2026-09-08 개정 · 화면 20장이 전부 정상 경로로 열린다.

값은 전부 `tools/mock/seed.mjs` 가 만드는 **기초 데이터**다. **기초 데이터가 바뀌면 이 문서가
조용히 틀려진다** — 값이 안 맞으면 그 파일을 먼저 본다.

⚠ **기초 데이터의 날짜는 목 서버를 띄운 날을 기준으로 만들어진다.** 입하일·계획일처럼 날짜가 든 값은
그날에 맞춰 움직이고, 번호·코드·수량은 고정이다. 이 문서가 날짜를 적지 않는 것은 그래서다.

## v2 에서 조작이 바뀐 자리

아래 셋은 **모든 화면**에 걸린다.

- **스캔이 기본이다.** 손으로 칠 때는 **「직접 입력」을 눌러야** 칸이 나온다 — 누르면 그
  칸에 바로 초점이 간다. 스캔 칸 옆에 나란히 서 있던 칸은 없어졌다.
- **스캔 안내 문구가 바뀌었다.** 「…을 비추세요」였던 자리가 **「…을 스캔하세요」**다.
- **고르는 자리는 고르는 표시로 보인다.** 자재 출고·피킹의 라인이 단추 목록에서 고르는
  목록으로 바뀌었다.
- **보내지 못한 것의 이름이 바뀌었다.** 「미동기」·「되돌아옴」이 **「전송 대기」·「전송 실패」**
  이고, 화면 이름은 **「전송 실패한 기록」**이다. 홈 맨 아래 묶음도 「셸」에서 「전송 상태」로
  바뀌었다.

> 바코드 이미지는 이 문서에 없다. 값만 있다. 스캔이 필요하면
> `apps/mobile/scripts/emulator-scan.sh <값>` 으로 넣거나, `qrencode` 로 직접 굽는다.

## 먼저 — 목 서버를 띄운다

```bash
pnpm mock
```

하나면 된다. 단말은 그 주소를 본다.

**이 서버는 상태를 갖는다.** 적치를 끝내면 지시가 목록에서 빠지고, 입하를 등록하면 누적
입하가 는다. 처음부터 다시 하려면 서버를 재시작한다.

## `M-01-01` 입하 등록

「입하」 타일 → 입하 등록 → 자재 LOT 스캔 → P/O 선택 → 실입하 수량.

| 넣을 칸     | 값                      |                                     |
| ----------- | ----------------------- | ----------------------------------- |
| 자재 LOT    | `…0007`                 | 스캔 · 손으로 칠 때는 「직접 입력」 |
| 발주 번호   | `PO-2026-000123`        | 고르는 칸                           |
| 발주 라인   | `ABC-123` 하우징 커버 A | 남은 예정 300 인 줄                 |
| 실입하 수량 | `300` / `311` / `200`   | 정상 · 초과 · 부족                  |
| 포장 수     | `10`                    | 비워도 등록된다                     |
| 제조일      | `2026-08-20`            | 비워도 된다                         |
| 유효기한    | `2027-08-19`            | 제조일보다 앞서면 막힌다            |
| 명세서 번호 | `DN-2026-000045`        | 비우면 「없습니다」만 말하고 진행   |

1번 줄은 발주 500 · 누적 200 이라 **남은 예정이 300** 이다. 두 수가 칸 옆에 함께 선다 —
판정이 견주는 것은 **남은 예정**이지 발주 총량이 아니다.

허용은 **+10 / −5** 다. 경계를 실제로 눌러 확인했다.

- ✅ `300` · `310` — 정상 (허용 안)
- ⚠ `311` — 초과. 남은 예정과 이번 도착을 함께 말한다
- ✅ `295` — 정상 (허용 안)
- ⛔ `294` · `200` — 부족. **네 수와 두 갈래**가 열린다. 「계속 등록」을 골라야 확정된다

⭐ 등록하면 **누적 입하가 실제로 는다.** 다시 열면 남은 예정이 줄어 있다.

**스캔값** — `0001234500000012002607310001230007` · `0001234500000012002607310001230008`

## `M-01-08` 자재 출고·피킹

「피킹/출고」 타일 → 자재 출고·피킹.

| 넣을 칸   | 값                                   |                     |
| --------- | ------------------------------------ | ------------------- |
| 피킹 지시 | `PK-2026-000077`                     | 목록에서 고른다     |
| LOT       | `0001234500000012002607310001230007` | ABC-123 하우징 커버 |
| 출고 수량 | `200`                                | 지시 수량과 같게    |

- ⭐ **라인은 줄 왼쪽의 고르는 표시를 눌러 고른다** — 줄마다 선출 순위가 오른쪽에 붙는다
- ⛔ **보류 라인은 고를 수 없다.** 흐리게 서고 그 줄에 보류 사유가 붉게 뜬다
- ⛔ 지시에 없는 LOT 을 스캔하면 막힌다 — 오투입을 여기서 잡는다
- ⭐ 「출고 확정」은 **한 라인 이상 집고 출고 유형을 고르면** 열린다. 다 집을 필요는 없다 —
  보류 라인이 있으면 애초에 다 집을 수 없다
- ℹ 머리의 `1 / 3 · 보류 1` 에서 **보류는 분모에만 든다.** 집을 수 있는 것을 다 집어도
  분자가 분모에 닿지 않는다

## `M-04-04` 제품 입고·적치

「출하 스캔」 타일 → 제품 입고·적치. 제품 LOT 이 여기서 **완제품 재고로 선다**.

| 넣을 칸   | 값               |                    |
| --------- | ---------------- | ------------------ |
| 입고 창고 | 1공장 완제품창고 | 물건이 들어갈 창고 |
| 인식표    | `HU-2026-000058` | QR 스캔            |
| 1번 줄    | `180`            | `FLOT-2026-0311`   |
| 2번 줄    | `60`             | `FLOT-2026-0305`   |
| 적치 위치 | `FG-A-02-01`     | 스캔               |

- ⚠ 인식표 수량과 다르면 말하되 **막지 않는다** — 차이 사유를 담을 자리가 계약에 없다
- ⚠ 검사 대기 LOT 도 **입고된다** — 막히는 것은 하류의 피킹·출하다
- ⭐ 입고가 서면 적치 완료를 **이어서** 부른다. 오프라인이면 입고만 담기고 적치는 적치 화면에서 잇는다
- ⚠ 인식표 경로는 **아직 개발 백엔드에 없다** — 목 서버로만 확인한다

## 전송 상태 · 전송 실패한 기록

위쪽 띠에 빨간 「전송 실패 N」이 뜨면 누른다. 무엇이 언제 왜 실패했는지 보인다.
홈 목록 맨 아래 「전송 상태」 묶음에서도 들어간다.

- ⚠ **다시 보내는 단추가 없다** — 거부는 다시 보내서 풀리는 것이 아니다
- ℹ 기내 모드로 바꾸고 쓰기를 하면 「담아 두었습니다」가 뜨고 칩이 **「전송 대기 N」**이 된다
  — 그것은 기다리면 간다. 「전송 실패」와 다르다

## 이 값들은 어디서 왔나

전부 **합성값**이다. 실 사번·실 품목·실 거래처가 아니다.

`PO-2026-000123` · `IR-2026-000210` · `DN-2026-000045` 처럼 계약 정본의 `example` 을 그대로
쓴 것이 여럿이고, 그 값들은 **생성 API 타입에 이미 들어와 있다**. 자리표시(「값」·「문자열」)인
자리만 같은 결로 지어냈다 — 판단 근거는 `tools/mock/seed.mjs` 머리에 적혀 있다.

## 서버에 아직 없는 경로

재고 이동(`M-01-10`) · 실물 카운트(`M-01-11`) · 제품 입고(`M-04-04`)가 부르는 경로는 개발
백엔드에 아직 서지 않았다. 그 셋은 **목 서버로만** 확인한다. 나머지 화면은 둘 다 된다.

목록은 `/api/docs-json` 의 표제에서 얻는다 — `⛔ 미구현 —` 이 붙은 것이 그것이다.
