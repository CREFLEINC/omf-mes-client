# POP 설치본 굽기

Windows 단말에 올릴 설치본(`.exe`)을 만드는 절차다. 개발 중 화면 확인은 설치본이 아니라
`pnpm --filter @omf-mes/web dev:pop` 으로 한다.

## 백엔드를 어떻게 부르는가 — 셸이 대신 부른다

설치본의 화면 주소는 `pop://app` 이다. 백엔드는 언제나 **다른 출처**이고, 백엔드가 교차 출처
허용 헤더를 주지 않으면 서버가 멀쩡히 답해도 화면은 응답을 읽지 못한다(실측: `curl` 은 401 을
받는데 같은 요청이 화면에서는 `Failed to fetch`).

그래서 **화면은 자기 주소(`pop://app/api/...`)만 부르고, 셸이 그 요청을 백엔드로 대신 보낸다**
(`src/main/api-relay.ts`). 안드로이드 앱이 `CAP_NATIVE_HTTP` 로 푼 것과 같은 자리다.

- 화면 쪽 기준 URL 은 POP 번들 빌드의 **기본값이 `pop://app/api`** 다(`apps/web/vite.pop.config.ts`)
- 셸 쪽 목적지는 **`POP_API_TARGET` 으로 굽는 사람이 준다** — 저장소에 주소를 적지 않는다

## 굽는 순서

```bash
# 1) 화면 번들 — 환경변수를 주지 않는다(기본값이 중계다)
pnpm --filter @omf-mes/web build:pop

# 2) 셸 + 설치본 — 백엔드 «원점»을 준다
POP_API_TARGET=http://<백엔드-호스트>[:포트] pnpm --filter @omf-mes/pop dist
```

산출물은 `apps/pop/release/` 에 떨어진다.

## 함정 셋

| 함정                                | 결과                                | 바로잡기                           |
| ----------------------------------- | ----------------------------------- | ---------------------------------- |
| `POP_API_TARGET` 에 `/api` 를 붙임  | 요청이 `/api/api/...` 로 나간다     | 원점만 준다. 빌드가 거절한다       |
| 화면 번들에 실서버 절대 주소를 박음 | 중계를 건너뛰어 다시 CORS 에 막힌다 | `VITE_API_BASE_URL` 을 주지 않는다 |
| `POP_API_TARGET` 없이 릴리스        | 켜지지만 아무것도 못 부르는 설치본  | 빌드가 멈춘다                      |

## 빌드 경로는 얕게

`makensis` 는 경로가 깊으면 **말없이 죽는다**(실측). 저장소가 깊은 곳에 있으면 `~/omfpb` 처럼
짧은 경로에 워크트리를 두고 굽는다.

## 목 서버를 가리키는 설치본

화면 동작만 보려면 목을 가리키게 구울 수 있다. **이때는 중계를 쓰지 않는다** — 목의 경로에는
`/api` 접두가 없어 중계가 넘길 대상이 아니고, 목은 교차 출처를 열어 두므로 화면이 절대 주소를
그대로 불러도 된다.

```bash
VITE_API_BASE_URL=http://127.0.0.1:4010 pnpm --filter @omf-mes/web build:pop
POP_API_TARGET=http://127.0.0.1:4010 pnpm --filter @omf-mes/pop dist
```

⚠ 두 번째 줄의 `POP_API_TARGET` 은 이 경우 **쓰이지 않는다.** 릴리스 빌드가 값을 요구하므로
같은 주소를 넣어 둘 뿐이다 — 실서버용으로 잘못 구워 나가는 것보다 낫다.
