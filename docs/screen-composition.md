# 화면 구성 규범

화면 하나를 **어떤 틀로 구성하는가**의 기록이다. 배치 규범(`layout-conventions.md`)이 블록 사이 간격과 정렬을 정한다면, 이 문서는 그보다 한 단계 위에서 화면의 유형, 영역 구성, 선택 후 이동, 절차 표시, 주 동작 위치를 정한다.

목표는 하나다. **처음 쓰는 사람이 사용 방법과 업무 절차를 고민하지 않고 바로 쓸 수 있는 화면.** 그러려면 어느 화면을 열어도 다음 세 가지가 같은 자리에서 보여야 한다.

1. 무엇을 선택하는가
2. 선택하면 어디로 가는가
3. 다음에 무엇을 누르는가

## 이 문서의 범위

**담는 것**

- 화면 유형과 유형 판정 기준
- 유형별 영역 구성, 선택 후 이동, 단계 표시, 주 동작 위치
- 셸과 유형에 공통인 구성 규칙(행 선택, 비활성 사유, 확인 단계, 검증 시점, 크기 검증)
- 화면 안 요소의 시각 위계(제목 단계, 조회 조건 칸 폭, 버튼 크기와 모양, 안내 상자). 값은 디자인 시스템 토큰 이름으로만 정한다(C-19)
- 규칙을 구현하는 공용 부품의 명세

**담지 않는 것**

- 블록 간격과 정렬 값: `layout-conventions.md`
- 컴포넌트 내부의 치수, 색, 상태: 디자인 시스템(`@crefle/web-ui`). 이 문서는 어느 토큰을 어느 자리에 쓰는지만 정한다
- 화면별 필드의 의미와 업무 규칙: 업무 이슈(omf-all-around)와 서버 계약(omf-mes-server `contracts/`)

**구성 판단의 기준.** 규칙을 적용할 때 먼저 사용자의 작업 순서(무엇을 어떤 단위로 끝내고 다음으로 가는가)를 확인한다. 측정값(높이, 폭)을 맞추려고 작업 흐름을 쪼개거나 순서를 바꾸지 않는다. 넘치면 보여 줄 필요가 없는 것(자동으로 채워져 손댈 일이 없는 값)부터 줄인다.

**서술 방식.** 배치 규범과 같이 **기본값 하나와 이탈 조건을 함께 적는다.** 「상황에 따라 다르다」로 쓰면 규범이 아니다. 이탈하면 화면 파일 머리 주석과 완료 보고에 이탈한 규칙 번호와 근거를 적는다.

**근거와 우선순위.** 화면의 구성(유형, 영역, 선택 후 이동, 단계, 주 동작 위치, 표시할 정보, 화면과 메뉴 이름)은 **이 규범이 정한다.** 필드의 의미와 업무 규칙과 용어는 업무 이슈(omf-all-around)와 서버 계약(omf-mes-server `contracts/`, 클라이언트 생성 타입)을 따른다. 규범이 요구하는 정보나 결정이 이슈와 계약에 없으면 C-15에 따라 요청한다. 이슈 본문이 화면 배치를 적었더라도 구성은 이 규범대로 만들고, 차이는 그 이슈에 남긴다.

- **공개 범위.** omf-all-around, omf-mes-client, omf-mes-server는 모두 공개 저장소다. 화면 캡처는 이슈, PR, 댓글 어디에도 올리지 않는다(시험 DB에 실제 기준 정보가 있을 수 있다). 대신 이슈에 글로 잘 적는다: 화면과 경로, 재현 순서, 기대한 것과 실제 결과, 관련 규칙 번호. 서버 결함과 계약 문제는 omf-mes-server 이슈, 업무 결정은 해당 업무 이슈(omf-all-around)에 적는다. 실제 기준 정보 값(품목명, 거래처명, 작업자 이름 등), 고객사명, 내부 주소, 계정은 적지 않고 「품목 A」처럼 일반화해 쓴다.
- 클라이언트 워크플로의 「이미 개발된 화면의 디자인은 최대한 수정하지 않는다」는 구성 변경이 없는 작업에 적용한다. 화면 구성을 바꾸는 작업에서는 이 규범이 우선하고, 그 화면이 재사용하는 기존 부품도 C-20에 따라 함께 맞춘다.

**규칙 번호.** 유형 규칙은 `T-`, 공통 규칙은 `C-`로 시작한다. 검사 스크립트와 점검표는 이 번호로 위반을 보고한다.

**기준 예시.** 관리웹 처리형의 기준 구현은 「ERP W/O 처리」(생산계획 흐름, `apps/web/src/screens/production-order/`)다. 작업함, 처리 화면 단계, 하위 항목 편집, 일괄 동작 결과가 이 규범대로 만들어져 있다. 규칙과 기준 구현이 다르면 규칙이 우선이고, 차이는 둘 중 하나를 고쳐 맞춘다.

## 1. 화면 유형 판정

새 화면을 만들거나 기존 화면을 크게 고칠 때 **먼저 유형을 정한다.** 업무 이슈와 서버 계약(이 화면이 부르는 API)을 읽고 아래 질문에 차례로 답한다. 처음 「예」가 나온 유형이 그 화면의 유형이다.

### 관리웹

| 순서 | 질문                                                                                                      | 「예」면         |
| ---- | --------------------------------------------------------------------------------------------------------- | ---------------- |
| 1    | 화면의 목적이 지표와 현황을 한눈에 보는 것인가(대시보드, 집계)                                            | **W-D 현황형**   |
| 2    | 대상을 고른 뒤 **두 단계 이상**을 거쳐 확정, 처리, 발행하는가(입고 확정, 출하 처리, 실사 마감, 판정 전이) | **W-C 처리형**   |
| 3    | 기준 정보를 등록, 수정, 사용 중지하는가(마스터, 코드, 규칙, 권한)                                         | **W-B 마스터형** |
| 4    | 그 밖에 목록을 조회하고 상세를 보는가(현황 조회, 이력 조회)                                               | **W-A 조회형**   |

- 처리형 판정의 「단계」는 사람이 처리 화면 안에서 한 묶음으로 정하는 일이다. 작업함에서 대상을 고르는 것은 단계에 넣지 않는다. 확인과 확정은 한 단계(마지막 확인 단계에서 확정 버튼을 누른다)로 센다. 처리 화면 안에서 정할 것이 두 묶음 이상이면 처리형이다. 대상을 고르고 바로 한 번 누르면 끝나는 일(승인, 반려)은 조회형 상세 안의 동작으로 둔다.
- 한 화면이 두 유형에 걸치면(예: 목록 조회와 처리를 함께) **처리 부분을 처리형 화면으로 분리**하고, 원래 화면은 처리형의 작업함이 된다.

### POP

| 순서 | 질문                                                                                                     | 「예」면       |
| ---- | -------------------------------------------------------------------------------------------------------- | -------------- |
| 1    | 작업지시(W/O)나 작업 세션을 전제로 하는 일인가(투입, 실적, 검사, 중단, 부품 교체, 포장, 툴 사용, 비가동) | **P-W 작업형** |
| 2    | W/O와 무관한 단독 작업인가(라벨 발행, 출고 QR, 위치 라벨)                                                | **P-S 단독형** |

### 모바일(PDA)

| 순서 | 질문                                                                      | 「예」면       |
| ---- | ------------------------------------------------------------------------- | -------------- |
| 1    | 업무 메뉴의 진입 화면인가                                                 | **M-H 홈**     |
| 2    | 스캔이나 선택을 거쳐 등록, 확정하는가(입하, 적치, 피킹, 이동, 실사, 점검) | **M-S 단계형** |
| 3    | 스캔한 대상의 정보를 보기만 하는가(자재 위치 확인)                        | **M-V 조회형** |

## 2. 관리웹 유형별 구성

### T-W-A 조회형: 목록과 상세 드로어

**기준.**

| 영역(위에서 아래) | 내용                                                                        |
| ----------------- | --------------------------------------------------------------------------- |
| 페이지 머리       | `PageHeader`. 제목, 탐색 경로, 화면 전체 동작(엑셀 내보내기 등)은 `actions` |
| 조회 조건         | 한 줄. C-6                                                                  |
| 목록              | 전체 폭 표. 행 전체 클릭(C-1). 아래에 페이지 이동(C-8)                      |
| 상세              | **오른쪽 드로어**(`Dialog placement="right"`). 목록은 유지                  |

- 행을 누르면 드로어가 열리고, 드로어 머리에 대상 번호와 닫기가 있다. 닫으면 목록의 같은 위치로 돌아간다.
- 드로어 안에서 다른 화면으로 가야 하는 동작(예: 처리하기)은 링크 버튼으로 해당 화면을 연다. 드로어 안에 또 목록을 쌓지 않는다.
- 선택한 대상은 주소 쿼리(`?selected=`)에 남겨 새로고침과 공유에 대응한다.

**이탈 조건.**

- 상세가 표 한 줄을 더 보는 정도(필드 3개 이하)면 드로어 대신 행 펼침을 써도 된다.
- 상세에 다시 목록(이력, 라인)이 필요하면 드로어 안 탭 한 겹까지 허용한다. 그보다 깊으면 상세를 별도 화면으로 분리한다.

### T-W-B 마스터형: 목록과 편집 패널

**기준.**

| 영역           | 내용                                                    |
| -------------- | ------------------------------------------------------- |
| 페이지 머리    | 제목, `actions`에 [신규 등록]                           |
| 검색           | 한 줄. 마스터는 조건이 적으므로 검색어와 사용 여부 정도 |
| 본문           | 좌우 2단. 왼쪽 목록(행 전체 클릭), 오른쪽 편집 패널     |
| 편집 패널 하단 | 저장 하나(C-3). 취소, 사용 중지는 왼쪽 보조 동작        |

- **2단은 1280×800에서 유지한다.** 왼쪽 목록은 핵심 열(코드, 이름, 상태) 3~4개로 줄이고 최소 폭 280px, 오른쪽은 나머지 폭을 쓴다. 편집 패널의 폼이 2열을 유지할 폭이 안 되면 패널 안에서 1열로 접는다(배치 규범 5 개정 제안 참고).
- 하위 항목(버전, 공정, 검사 항목)은 편집 패널 안 탭 한 겹까지. 하위 항목을 고쳐도 저장은 패널 하단 하나다.
- 저장하지 않은 변경이 있는 상태에서 다른 행을 누르면 확인을 받는다.

**이탈 조건.**

- 하위 항목이 독립된 수명을 가지면(별도 승인, 별도 이력) 하위 편집 화면을 분리하고 패널에는 목록과 [편집] 링크만 둔다.
- 필드가 적은 코드성 마스터(필드 4개 이하)는 편집 패널 대신 행 편집 대화상자를 써도 된다.

### T-W-C 처리형: 작업함과 처리 화면

여러 단계를 거쳐 확정하는 업무는 **목록 아래에 쌓지 않고 처리 화면으로 넘어간다.** 이 유형이 이 문서의 핵심이다.

**작업함(목록 화면) 기준.**

| 영역        | 내용                                                                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 페이지 머리 | 제목, 그 아래 조건 칩 줄(상태별 건수, C-17). 조건 칩이 처리 대기 건수를 대신하므로 별도 「처리 대기 N건」 문장을 두지 않는다                                                         |
| 조회 조건   | 한 줄. 기본값으로 「처리 대기만」을 켠다                                                                                                                                             |
| 목록        | 행 전체 클릭으로 처리 화면 이동. 열: 식별 번호, 상대(공급사, 고객), 일시, 문서 번호, 처리 대기 수(예: 1 / 4 라인), 처리 판단에 쓰는 상태 구성(예: 판정 칩), 마지막 열은 이동 표시(›) |

- 목록에서 처리 판단에 필요한 정보(처리 대기 수, 판정이나 상태의 구성)를 보여 준다. 사용자가 행을 열어 보기 전에 어느 건부터 할지 정할 수 있어야 한다. 이 정보가 계약에 없으면 C-15에 따라 추가를 요청한다. 숨기는 것으로 대신하지 않는다.
- 처리할 수 없는 건은 목록에 그대로 두되 상태 칩으로 이유를 알린다.
- 작업함의 주 동작은 행 이동이다. 조회 조건의 [조회]는 조건 영역의 채움 버튼으로 C-3의 「영역마다 하나」에 맞는다. 일괄 동작이 있으면 페이지 머리 `actions`에 둔다.
- 일괄 동작이 있는 작업함은 첫 열 체크박스로 대상을 고르고, 행의 나머지를 누르면 처리 화면으로 간다(C-1의 예외). 체크박스 칸을 눌러도 이동하지 않는다. 결과 표시는 C-18을 따른다.
- 서버가 자동으로 처리한 결과를 사람이 검토하는 업무는 C-17을 따른다. 기본 조건은 「확인 필요」이고, 자동으로 끝난 건은 일괄 동작으로 다음 단계에 넘긴다.

**처리 화면 기준.**

| 영역(위에서 아래) | 내용                                                                                                                                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 처리 머리         | 왼쪽 위 [← 〈작업함 이름〉], 제목은 대상 번호(작업함 제목과 같은 제목 크기, C-19), 옆에 상태 칩과 사유 칩. 그 아래 한 줄에 대상 요약(상대, 품목, 수량, 일시, 문서 번호). 줄 수는 상태와 관계없이 두 줄로 고정한다 |
| 단계 표시         | 가로 단계 표시(`ProcessStepper`). 단계는 2~4개                                                                                                                                                                    |
| 지난 단계 요약    | 점선 상자 한 줄. 지난 단계에서 정한 값만. 형식은 아래 「지난 단계 요약 형식」                                                                                                                                     |
| 단계 본문         | **현재 단계 하나만** 표시. 구획 제목은 명사형                                                                                                                                                                     |
| 하단 동작 바      | 화면 아래 고정, 스크롤 영역 밖. 왼쪽에 「남은 일」 한 줄(C-5), 오른쪽에 [이전]과 [다음: 〈다음 단계 이름〉], 마지막 단계는 [〈업무 동사〉](주 동작)                                                               |

**단계 이름.** 그 단계에서 정하는 대상을 업무 용어(이슈와 계약의 용어)로 쓴 명사형 2~6자다(예: 라인 선택, 입고 정보, 확정 확인). 단계에 넣는 칸이 바뀌면 이름도 그 묶음에 맞게 바꾼다. 마지막 단계 이름은 「확정 확인」처럼 〈업무〉 확인으로 통일한다.

**지난 단계 요약 형식.** 값을 문장처럼 이어 붙이지 않고, 단계별 묶음과 「라벨 값」 쌍으로 쓴다.

- 단계마다 묶음 하나. 묶음 앞에 단계 이름(`--type-label-sm`, 흐린 색)을 두고, 묶음 사이는 세로 구분선으로 나눈다.
- 묶음 안은 「라벨 값」 쌍이다. 라벨은 흐린 색 `--type-label-sm`, 값은 `--type-body-sm`. 쌍 사이는 간격(`--space-4`)으로 나눈다. 쉼표, 빗금(/), 가운뎃점으로 값을 잇지 않는다.
- 예: 「마스터 점검 │ BOM DEMO-BOM-CASE (Rev 1)　Routing DEMO-RT-CASE (Rev 1) ║ 생산계획 │ 확정 수량 500 EA　라인 사출 A라인 (DEMO-LN-A)」 (│는 단계 이름 뒤 간격, ║는 묶음 구분선을 뜻한다)
- 정해지지 않은 값(라인 미지정)은 빼지 않고 「미지정」을 경고 색 글자로 보인다. 다음 단계의 할 일과 이어지기 때문이다.
- 한 줄에 다 들어가지 않으면 묶음마다 한 줄로 나눈다. 묶음 안에서 줄바꿈하지 않는다.

**주소와 이동.**

- 처리 화면 주소는 작업함 아래 경로에 **사용자에게 보이는 업무 번호**를 쓴다(예: `/logistics/goods-receipt/IR-2026-000210`). 내부 식별자는 쓰지 않는다. 업무 번호로 대상을 조회하는 계약이 없으면 C-15로 요청한다.
- 단계와 처리 화면 안의 선택(라인 등)은 주소에 넣지 않고 이력에 쌓지 않는다(`replace`). 브라우저 뒤로가기는 [← 작업함]과 같은 결과를 낸다.
- **완료한 단계는 단계 표시에서 눌러 돌아갈 수 있다.** 입력한 값은 유지한다. 앞 단계에서 대상을 바꾸면 뒤 단계는 다시 진행한다. 아직 갈 수 없는 단계는 누를 수 없고, 하단 바의 「남은 일」이 그 이유를 말한다.
- **처음 여는 단계**는 데이터로 정한 첫 미완료 단계다. 서버 사유(C-17)와 실제 데이터가 다르면 데이터를 따른다. 사유와 단계의 대응표는 구성안에 적는다. 이미 끝난 대상을 열면 완료 화면을 연다.
- 작업함 결과 영역의 「고칠 곳」 링크도 같은 방식으로 연다. 단계는 주소에 넣지 않는다.

**중간 단계의 확정.** 다음 단계로 가려면 되돌릴 수 없는 확정이 필요한 단계(예: 계획을 확정해야 W/O가 생기는 생산계획 단계)는 하단 바 주 동작이 [다음: 〈단계〉]가 아니라 [〈확정 동사〉](예: [전개 확정])다. 누르면 C-9 확인 창(대상, 생기는 것과 수, 「〈확정〉 시 반영 사항」, 되돌릴 수 없다는 안내)을 거쳐 확정하고 **바로 다음 단계로 넘어간다.** 표 행 안에 확정 버튼을 두지 않는다. 단계 안 입력(행의 계획일, 수량, 라인)은 별도 [저장] 없이 확정할 때 함께 저장한다. 저장만 하고 나가는 길이 필요하면 하단 바 왼쪽에 [임시 저장](테두리)을 둔다.

**단계 본문.**

- 한 단계 안의 입력 칸은 **처음부터 모두 열어 둔다.** 앞 칸을 채워야 뒤 칸이 열리는 순차 개방은 쓰지 않는다(배치 규범 4와 충돌). 다른 칸의 값에 따라 범위가 정해지는 칸(창고에 따른 위치)은 C-12의 「의존 관계」를 따른다(앞 값이 비어도 팝업에서 함께 고를 수 있게 한다).
- 업무 규칙에서 정해지는 값(판정에서 승계되는 상태 등)은 입력 칸이 아니라 **읽기 전용**으로 출처와 함께 보여 준다. 바꿀 수는 있지만 대부분 기본값 그대로 쓰는 값(라인 기본 위치, 교대 기준 계획 시각)은 요약 한 줄과 [변경]으로 접는다(「높이가 모자랄 때」 ①). 값을 정하는 규칙이 업무 이슈에서 정해지지 않았으면 C-15로 결정을 요청하고, 결정 전까지는 입력 칸으로 두되 구성안에 「확인 필요」로 적는다.
- 선택 입력(사유, 비고)은 「추가 입력(선택)」으로 접는다.
- **서버가 허용하는 진행을 화면이 막지 않는다.** 비어 있어도 서버가 받는 값(예: 계획 라인)이 다음 단계에서 다시 손이 가게 만든다면, 「남은 일」에 권고로 알리고(예: 라인을 정하면 4M 배정이 자동으로 채워집니다) 주 동작은 잠그지 않는다. 막아야 할 업무 규칙이면 업무 이슈에 결정을 요청한다(C-15).
- 기준 정보로 정해지는 기본값(적치 규칙의 위치 등)이 있고 그 값을 주는 API가 있으면 「추천 적용」 버튼을 둔다. 다른 칸을 바꿀 때 자동으로 채워지는 값(라인을 고르면 라인 기본 위치)은 버튼 대신 그 칸 라벨의 ⓘ 툴팁으로 알린다. API가 없으면 C-15로 요청한다.

**마지막 확인 단계.**

- 저장될 값의 핵심(대상, 수량, 위치 같은 결과를 바꾸는 값)과 「〈업무〉 시 반영 사항」(`EffectList`, 명사형 목록, 예: 입고 전표 생성, 자재 LOT 상태 변경: 가용)을 **1280×800 첫 화면 안에** 보여 준다. 지난 단계 요약과 같은 내용을 다시 늘어놓지 않는다.
- 조건에 따라 빠지는 반영 사항(예: 한도승인 건의 ERP 송신 제외)은 지운 줄과 경고로 표시한다. 그 조건을 처리 전에 판정할 데이터가 없으면 C-15로 요청한다.
- 되돌릴 수 없으면 「확정 후에는 수정할 수 없습니다. 〈취소 방법〉으로 처리합니다.」를 둔다. 취소 방법은 서버 계약의 동작 이름을 업무 용어로 쓴다(예: 역분개, W/O 취소).
- 확정 요청에서 서버가 특정 칸의 검증 오류를 돌려주면, 그 칸이 있는 단계로 이동해 칸에 오류를 표시한다. 접힌 구획에 있으면 펼친다.

**완료 화면.**

- 단계 표시는 모두 완료로 바뀌고 누를 수 없다.
- 성공 알림에 결과 번호, 결과 요약(상태 변화, 연계 송신 상태)을 업무 용어로 보여 준다. 코드값(`POSTED`, `NORMAL`)은 코드 사전의 이름으로 바꿔 보인다. 응답 구조나 화면 처리 방식을 설명하는 문장은 두지 않는다(C-13).
- 하단 바 오른쪽 주 동작은 **다음 처리 대상**이다. 같은 대상 안에 처리 대기 항목(다음 라인)이 남았으면 [다음 〈항목〉 처리], 없으면 작업함의 다음 처리 대기 건으로 [다음 〈대상〉 처리]. 다음 건은 사용자가 마지막으로 본 작업함 목록(조건, 정렬, 행 순서를 처리 화면을 열 때 기억해 둔다)에서 현재 건 다음 행이다. 현재 건이 처리되어 조건에서 빠져도 기억한 순서로 정한다. 그 왼쪽에 [〈작업함 이름〉으로]. 「남은 일」 자리에는 남은 항목 수를 보인다.

**나뉜 화면 합치기.** 같은 업무의 작업함은 하나다. 메뉴에 있는 화면이라도 하는 일이 이 업무의 일괄 동작이나 처리 화면의 마지막 단계와 같으면 합치고 메뉴에서 뺀다. 옛 주소는 작업함의 해당 조건으로 넘긴다. 합치면 없어지는 길(예: 하위 항목 하나만 따로 처리)이 있으면 구성안과 업무 이슈에 적는다.

메뉴에 없고 앞 화면의 이동 버튼과 주소의 대상 번호로만 들어가는 화면이 같은 업무의 다음 단계라면, 별도 화면으로 두지 않고 처리 화면의 단계로 합친다. 판단 기준은 「그 화면을 대상 없이 열 일이 있는가」다. 없으면 단계다. 합치면서 메뉴가 바뀌면 같은 작업에서 메뉴(`nav-tree.ts`)와 화면 목록을 함께 고친다.

**대상 안의 하위 항목.** 한 대상 아래 하위 항목이 여럿이고 단계에서 항목마다 값을 정해야 하면(ERP W/O 아래 공정별 W/O의 4M 배정), 단계 본문을 왼쪽 하위 항목 목록과 오른쪽 편집 영역의 2단으로 둔다. 편집 영역은 1280×800에서 스크롤 없이 들어와야 한다. 칸은 3열 격자로 놓고 구획 상자를 겹치지 않는다(상자 안 상자 금지, 구획은 소제목과 구분선). 편집 영역 아래에 [저장](테두리)을 두고, 채움 버튼은 하단 바 주 동작 하나다. 저장하지 않은 변경이 있으면 하단 바 주 동작이 잠기고 「남은 일」이 저장할 항목을 말한다. 다른 항목을 누르면 저장하지 않은 변경을 확인한다. 하위 항목 목록에는 항목별 완료 여부를 칩으로 보이고, 「남은 일」은 미완료 항목 수와 첫 미완료 항목의 할 일을 말한다(예: W/O 2건 미배정. 조립 공정의 기본 WIP 위치를 고르세요).

- **높이 배분(관리웹 1280×800).** 셸 탭 막대, 처리 머리 두 줄, 단계 표시, 지난 단계 요약 한 줄, 하단 바를 빼면 단계 본문은 약 400px이다. 편집 영역은 머리 한 줄(편집 중인 항목의 번호와 이름, 오른쪽에 테두리 버튼들)과 묶음 줄로 채운다. 점검 결과는 머리 아래 한 줄로 두고, 문장은 줄바꿈해 다 보인다.
- **편집 영역 칸 배치.** 고른 값(「이름 (코드)」)이 잘리지 않는 폭을 먼저 확보한다. 묶음(예: 설비와 금형, 작업자와 교대, 위치, 계획) 단위로 줄을 맞추고, 묶음 안 칸 폭은 같다. 묶음을 지키느라 생기는 빈칸은 허용한다. 폭이 모자라면 다음 순서로 확보한다. ① 묶음 제목을 칸 왼쪽 열에 두지 않고 묶음 위에 한 줄로 둔다(C-19 소제목 위치) ② 왼쪽 하위 항목 목록의 열을 줄인다(번호 열 생략 조건은 아래) ③ 열 수를 줄인다(3열 → 2열).
- **높이가 모자랄 때.** 편집 영역은 1280×800에서 본문 스크롤 없이 들어오는 것이 기본이다. 넘치면 다음 순서로 줄인다. ① **자동으로 채워지는 값을 접는다.** 다른 칸이나 기준 정보로 정해지는 기본값(라인을 고르면 채워지는 기본 위치, 계획일과 교대로 정해지는 계획 시각)은 입력 칸을 펼치지 않고 요약 한 줄(값과 출처, 예: 「라인 기본 위치: WIP 생산창고 라인공급 (DEMO-WIP-01), 완제품 …, 스크랩 …」)과 [변경]으로 둔다. 값이 비었거나 점검이 그 값을 막으면 펼쳐 보인다. ② 그래도 넘치면 편집 영역 안에서만 스크롤하고, 편집 영역 머리(항목 번호와 이름, 저장)는 고정한다. 구성안에 이탈로 적는다. **하위 항목 하나의 설정을 여러 단계에 나누지 않는다.** 사용자는 항목 하나를 끝내고 다음 항목으로 넘어가므로, 칸 묶음별로 단계를 나누면 같은 항목을 여러 번 찾아가게 된다.
- **하위 항목을 고르는 형태.** 기본은 왼쪽 목록이다. 하위 항목 수가 데이터에 따라 달라지고(예: W/O 수는 계획 수와 Routing 공정 수의 곱), 항목마다 상태를 나란히 보여야 하며, 작업함과 같은 행 선택 조작(C-1)을 쓰기 때문이다. 위쪽 탭(세그먼트)은 다음 셋을 모두 만족할 때만 쓴다. ① 업무 규칙상 항목 수가 항상 4개 이하로 고정이다 ② 탭 이름이 짧은 업무 용어 하나다 ③ 항목별 상태가 칩 하나로 충분하다. 편집 영역 폭이 모자라다는 이유로 목록을 탭으로 바꾸지 않는다(폭은 「편집 영역 칸 배치」 순서와 「한 단계는 한 화면」으로 해결한다).
- **항목 하나씩 끝내는 흐름.** 편집 영역에서 [저장]하면 다음 미완료 항목을 연다(공정 순서). 모두 끝나면 하단 바 주 동작이 다음 단계로 진행할 수 있다고 말한다. 「남은 일」은 다음 미완료 항목과 그 항목의 첫 빈 칸을 말한다(예: 조립 공정의 생산 라인을 고르세요).
- **왼쪽 하위 항목 목록.** 폭이 모자라면 대조용 번호 열을 빼도 된다. 단 그 번호는 편집 영역 머리와 행의 접근 이름에 있어야 한다(C-10의 「대조」는 같은 화면 안 어디서든 번호를 볼 수 있으면 충족한다).
- **저장하지 않은 변경.** 다른 항목을 누를 때, 단계 표시나 [이전]으로 단계를 떠날 때, [← 작업함]이나 브라우저 뒤로가기로 처리 화면을 떠날 때 모두 확인한다.

**이탈 조건.**

- 단계가 5개 이상이면 업무를 나눌 수 있는지 먼저 검토한다. 나눌 수 없으면 세로 단계 표시를 왼쪽에 두는 배치를 쓴다.
- 결재처럼 다른 사람의 승인을 기다리는 단계는 단계 표시에 넣되 「대기」 상태로 두고, 처리 화면을 닫아도 작업함에서 그 상태가 보이게 한다.

### T-W-D 현황형: 대시보드

**기준.** 지표 카드 줄, 추이 차트, 처리 대기 목록 순서. 카드와 목록 행은 해당 업무 화면으로 이동하는 링크다. 자동 갱신은 하지 않고 기준 시각과 [새로고침]을 머리에 둔다.

**이탈 조건.** 서버가 집계를 지원하지 않는 지표는 오류 배너가 아니라 카드 자리에 「집계 준비 중」 안내로 둔다(C-7).

## 3. POP 유형별 구성

POP 규칙은 다음을 전제로 한다. 관리웹과 같은 글자 밀도, 1024×768 전체 화면, 스크롤하는 구획을 정해 두고 나머지는 고정, 목록 선택은 `PopSelect` 팝업.

### T-P-W 작업형: W/O 고정과 작업 탭

**기준.**

| 영역         | 내용                                                                            |
| ------------ | ------------------------------------------------------------------------------- |
| 머리줄       | 셸이 제공하는 공용 머리줄(C-11). 스테이션명, 작업자, 현재 W/O와 공정, 통신 상태 |
| 왼쪽 작업 탭 | 투입, 실적, 검사, 중단, 부품 교체, 포장 등 그 W/O로 할 수 있는 일. 세로 탭      |
| 본문         | 선택한 탭의 내용. 스캔 칸과 입력                                                |
| 하단 동작 바 | 고정. 「남은 일」 한 줄과 주 동작 하나                                          |

- 작업자 확인(배지 스캔 기본, 키패드 보조)과 W/O 선택은 작업형 화면에 **들어오기 전 단계**에서 끝낸다. 작업형 화면 안에 사번 키패드를 두지 않는다.
- 선택한 W/O는 모든 작업 탭이 공유한다. 탭을 바꿔도 다시 고르지 않는다.
- W/O 목록 카드는 W/O 번호, 품목 코드와 품목명, 지시와 실적 수량, 상태 텍스트(미착수, 진행 중, 보류)를 보여 주고 진행 중인 W/O를 위에 둔다.
- 화면 이동 팝업([화면 이동])은 단독형 화면으로 가는 용도로만 쓴다.

**이탈 조건.** 탭이 7개를 넘으면 자주 쓰는 5개를 탭으로, 나머지는 [기타 작업] 하나로 묶는다.

### T-P-S 단독형

**기준.** 머리줄(C-11), 본문 좌우 2단(왼쪽 대상 목록이나 스캔, 오른쪽 입력과 미리보기), 하단 동작 바 고정. 목록 행이나 카드는 전체 터치로 선택한다(C-1).

## 4. 모바일 유형별 구성

모바일 규칙은 다음을 전제로 한다. 입력은 스캔이 먼저, 스크롤하는 구획을 정해 두고 나머지는 고정, 화면 예산(앱바 56 + 본문 + 하단 동작 72).

### T-M-H 홈

**기준.** 앱바 한 줄, 홈 스캔 칸(지시서, LOT, 위치를 스캔하면 해당 작업 화면으로 이동), 역할별 업무 묶음 타일(6개 내외, 2열). 업무 화면 20개를 한 줄로 늘어놓지 않는다.

### T-M-S 단계형: 한 화면 한 단계

**기준.**

| 영역           | 내용                                             |
| -------------- | ------------------------------------------------ |
| 앱바           | 한 줄. [←], 화면명, 상태 아이콘                  |
| 단계 표시      | 현재 단계와 전체(예: LOT 2/3)                    |
| 지난 단계 요약 | 한 줄씩 접힘                                     |
| 현재 단계      | 스캔 칸(진입 즉시 포커스)과 안내 한 줄           |
| 하단 동작 바   | 본문 밖 고정. 「다음: 〈할 일〉」과 주 동작 하나 |

- 단계가 끝나면 현재 단계를 한 줄 요약으로 접고 다음 단계를 펼친다. 지난 구획을 펼친 채 아래에 구획을 추가하지 않는다.
- 대상을 정하는 스캔을 다시 하면, 입력 중인 값이 있으면 교체 확인을 받는다(공용 `ScanReplaceDialog`).
- 목록 카드는 객체별 정의(C-10)를 따른다.
- 기준 사례: 적치(단계 표시), 설비 점검(진행률), 자재 위치(화면 골격).

### T-M-V 조회형

**기준.** 스캔 칸, 결과 카드, 하단 [다음 스캔]. 결과 카드의 행동(이동 등)은 해당 단계형 화면으로 보낸다.

## 5. 공통 규칙

### C-1 행 선택

**기준.** 표와 카드 목록은 **행 전체를 눌러 선택한다.** 선택된 행은 배경과 왼쪽 막대로 표시한다. 키보드 위아래 방향키로 이동, Enter로 선택한다.

- 여러 건을 고르는 표만 첫 열 체크박스를 쓴다. 한 표에 두 방식을 섞지 않는다.
- **접근 역할.** 누르면 다른 화면으로 가는 행은 `role="link"`와 접근 이름 「〈번호〉 〈화면 이름〉 열기」를 준다. 누르면 선택되는 행은 `aria-selected`로 선택을 알린다. 체크박스 접근 이름은 「〈번호〉 선택」이다.
- 편집, 삭제 같은 행 동작은 **오른쪽 고정 열**(가로 스크롤 중에도 보임)이나 행 끝 「⋯」 메뉴에 둔다.
- 끝 열 [선택] 버튼을 만들지 않는다. 첫 열 식별자를 링크 모양으로 꾸미지 않는다.
- 행 안에 보이는 동작 버튼은 두 개까지다. 그보다 많으면 「⋯」 메뉴에 넣는다. 처리형 단계의 주 동작(확정)은 행에 두지 않는다(T-W-C 중간 단계의 확정).
- **한 화면에 같은 이름의 버튼을 두 곳에 두지 않는다.** 행마다 반복되는 동작은 접근 이름에 대상을 붙인다(예: 「PP-20261020-0001 삭제」). 확인 창은 뒤 화면을 보조기기와 자동화 도구에서 숨긴다(`aria-modal`, 뒤 화면 `inert`).
- 구현: 공용 부품 `SelectableTable`(6장).

**이탈 조건.**

- 행마다 입력 칸만 있고 행을 눌러 할 일이 없는 편집 표(생산계획 표, 배포할 W/O 표)는 행 선택을 두지 않는다. 실측 검사는 「편집 표, 해당 없음」으로 본다.
- 행을 누르는 동작이 다른 화면 이동이고 선택 상태가 의미 없으면(작업함) 선택 표시 없이 이동만 한다.
- 일괄 동작이 있는 작업함은 체크박스(일괄 대상)와 행 클릭(처리 화면 이동)을 함께 쓴다(T-W-C).

### C-2 선택 결과의 위치

**기준.** 선택 결과(상세, 하위 목록, 입력 폼)를 **목록 아래에 추가하지 않는다.** 유형별로 드로어(조회형), 오른쪽 패널(마스터형), 처리 화면(처리형), 다음 단계(모바일 단계형)를 쓴다. 한 화면 안의 연속 선택은 2단(목록, 상세)까지다.

**이탈 조건.** 없음. 필요하면 유형을 다시 판정한다.

### C-3 주 동작

**기준.** 영역마다 채움(`filled`) 버튼은 하나다. 위치는 유형별로 고정한다.

| 유형                | 주 동작 위치                                                  |
| ------------------- | ------------------------------------------------------------- |
| 조회형              | 페이지 머리 `actions`(화면 전체 동작), 드로어 하단(대상 동작) |
| 처리형 작업함       | 행 이동이 주 동작. 일괄 동작은 페이지 머리 `actions`          |
| 마스터형            | 편집 패널 하단 오른쪽 [저장]                                  |
| 처리형, POP, 모바일 | 하단 동작 바 오른쪽                                           |

- 색 규칙은 C-19를 따른다. 채움 버튼(DS 주 색)은 주 동작 하나에만, 오류 색은 이상 상태에만 쓴다. 되돌릴 수 없는 동작(삭제, 취소 확정)은 색으로 따로 강조하지 않고 확인 창(C-9)으로 막는다. 사용자 전환, 단말 재등록 같은 보조 동작은 채움을 쓰지 않는다.
- 조회 조건 영역의 [조회]는 그 영역의 채움 버튼이다. 페이지 전체에서 영역마다 하나를 지키면 된다.
- 한 화면에 저장 버튼은 하나다. 버튼 이름은 상태에 따라 바꾸지 않는다(「사용 중지」가 「재개」로 바뀌는 등). 상태는 옆에 표시한다.

### C-4 비활성 사유와 쓸 수 없는 기능

**기준.** 배치 규범 4를 따른다. 여기에 두 가지를 더한다.

- 하단 동작 바의 주 동작이 비활성이면 바 왼쪽 「남은 일」 문장(예: 작업지시를 고르세요)이 그 사유다. 버튼에 `aria-describedby`로 잇는다.
- **선택할 수 없는 행은 상태 칩이 사유다.** 칩(예: IQC 대기) 옆이나 다른 열에 같은 뜻의 안내 문장을 다시 쓰지 않는다. 해제 방법처럼 칩만으로 알 수 없는 안내는 그 행에 툴팁으로 두고, 행을 누르면 하단 바 「남은 일」 자리에 한 줄로 보인다.
- **계약이나 기준 정보가 정해지지 않아 늘 쓸 수 없는 기능은 화면에 두지 않는다.** 「준비 중」 버튼, 늘 잠긴 입력 칸을 노출하지 않는다. 기능이 열리면 그때 추가한다.

**이탈 조건.** 업무 이슈가 「존재를 알려야 한다」고 명시한 기능은 비활성으로 두고 사유를 붙인다.

### C-5 단계 표시와 남은 일

**기준.** 두 단계 이상의 업무(처리형, POP 작업형의 각 탭, 모바일 단계형)는 단계 표시와 「남은 일」 한 줄을 둔다. 「남은 일」은 상황별로 아래 문형을 쓴다. 하단 바의 「남은 일」은 바 전체의 안내이므로 배치 규범 4의 「컨트롤 이름으로 시작」 대신 이 문형을 쓴다.

| 상황                                         | 문형                                                                            | 예                                                                                       |
| -------------------------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 사용자가 입력해야 함                         | 「〈칸 이름〉+을/를 입력하세요」, 「고르세요」(조사는 받침에 맞춘다)            | 적치 위치를 고르세요                                                                     |
| 사용자가 해결할 수 없음(기준 정보 미등록 등) | 「〈무엇〉이 등록되지 않아 진행할 수 없습니다. 〈담당〉에게 등록을 요청하세요」 | 재고 상태 코드가 등록되지 않아 진행할 수 없습니다. 기준정보 담당자에게 등록을 요청하세요 |
| 막힘 없음                                    | 「〈다음 단계 이름〉으로 진행할 수 있습니다」                                   | 확정 확인으로 진행할 수 있습니다                                                         |
| 마지막 확인 단계                             | 「〈업무 동사〉 후 수정 불가」                                                  | 배포 후 수정 불가                                                                        |
| 완료                                         | 「남은 〈항목〉 N건」                                                           | 남은 라인 1건                                                                            |

- 화면에는 「남은 일:」 같은 머리말을 붙이지 않고 문장만 보인다. 문형이 할 일을 말하므로 머리말이 없어도 뜻이 통한다(사용자 화면 확인 결정, 2026-10-23). 「남은 일」은 이 줄을 부르는 규칙 안의 이름이다.
- 조사는 앞 말의 받침에 맞춘다(을/를, 이/가, 으로/로). 「을(를)」처럼 둘 다 쓰지 않는다. 공용 함수 하나(`patterns/josa`)로 붙인다. 영문과 약어는 읽는 소리로 판정한다(BOM 「봄」, W/O 「오」, LOT 「랏」). 판정표는 공용 함수에 둔다.
- 칸이 모두 찼는데 점검(검증)이 막으면 「〈점검 결과의 첫 항목〉을 해결하세요」로 쓴다. 예: 설비 사출기 1호기의 같은 시간대 배정을 해결하세요.
- 마지막 확인 단계에서 입력이 비어 실행할 수 없으면, 처음 열 때부터 「남은 일」이 그 칸을 말하고 주 동작이 잠긴다. 자동으로 채워지는 값이 빈 경우이므로 C-7의 「처음 열 때 오류 표시 금지」와 충돌하지 않는다(오류 표시가 아니라 할 일 안내다).

### C-6 조회 조건 영역

**기준.** 페이지 머리 바로 아래 한 줄. 기본으로 보이는 조건은 1280×800에서 버튼과 함께 한 줄에 들어가는 만큼(C-19 「보통」 칸 기준 세 칸), 나머지는 [조건 더보기]. 작업함의 상태 조건은 페이지 머리 조건 칩(C-17)이 맡고, 조회 조건 영역에 같은 칸을 두지 않는다. [조회]는 오른쪽 끝 채움 버튼, [초기화]는 그 왼쪽. Enter로도 조회한다. 필드 아래 설명문을 두지 않는다(형식은 placeholder, 보충 설명은 ⓘ 툴팁). 날짜는 C-12.

### C-7 검증 시점과 오류 표시

**기준.** 화면을 처음 열었을 때 오류를 표시하지 않는다. 경고 색과 `role="alert"`는 실제로 막힌 상태에만 쓴다. 늘 보이는 업무 규칙 안내는 정보 색 안내 상자로 두고, C-19의 안내 상자 기준을 따른다. 필수값 검증은 포커스가 떠날 때와 실행할 때 한다. 서버가 지원하지 않는 기능이나 집계는 오류가 아니라 안내로 표시한다. 응답 형식 오류로 화면 전체가 깨지지 않게 화면 단위 오류 경계를 둔다.

### C-8 페이지 이동

**기준.** 공용 부품 하나. 목록 아래 오른쪽에 [처음] [이전] n/N [다음] [마지막], 왼쪽에 총 건수와 페이지 크기 선택(20, 50, 100건). 비활성 버튼에 사유 문장을 붙이지 않는다(위치로 자명).

### C-9 확정 전 확인과 다음 작업

**기준.** 되돌릴 수 없는 동작은 확인을 거친다. 처리형은 마지막 확인 단계가 그 역할을 하고, 그 밖의 유형은 확인 대화상자(대상 번호와 이름, 변경되는 값, 버튼은 〈동사〉와 취소)를 쓴다. 성공 후에는 결과와 **다음 작업으로 가는 버튼**을 둔다.

### C-10 목록 행과 카드의 정보

**기준 정보의 코드와 이름 표시.** 코드와 이름을 가운뎃점(`·`)이나 하이픈으로 한 칸에 잇지 않는다.

| 자리                                                              | 표시                                                                       | 예                                             |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------- |
| 표                                                                | **코드 열과 이름 열을 나눈다.** 머리글은 「〈대상〉 코드」, 「〈대상〉명」 | 공급사 코드 \| 공급사명, 품목 코드 \| 품목명   |
| 한 줄 안(입력칸, 처리 머리, 지난 단계 요약, 확인 요약, 안내 문장) | 「이름 (코드)」                                                            | (주)대한부품 (SUP-001), 1공장 자재창고 (WH-01) |
| 이름이 없는 대상(LOT, 문서 번호)                                  | 번호만                                                                     | IR-2026-000210                                 |

- 표에서 둘 중 하나만으로 충분하면(같은 화면 다른 영역에 이미 보이는 경우 등) 그 열만 둔다. 둘 다 두는 것이 기본이다.
- 이름 열이 남는 폭을 가져가는 긴 텍스트 열이 된다(C-16).
- **조회 범위가 바뀌어도 행과 카드의 항목은 같다.** 범위(이 설비, 전체 설비)나 조건에 따라 항목을 더하거나 빼지 않는다. 범위를 넓혔을 때만 필요한 항목(소속 설비)이 있으면 처음부터 늘 보인다(사용자 화면 확인 결정, 2026-10-23).

**기준.** 업무 객체(W/O, 입하 라인, 피킹 지시 등)마다 목록에 보일 필드와 순서를 한 번 정해 공용으로 쓴다. 굵게 강조하는 필드는 2개까지. 품목, 거래처, 창고 같은 기준 정보는 코드와 이름을 함께 보인다(표시 방식은 아래). 값이 없으면 그 줄을 숨기고 「알 수 없음」, 「있음/없음」 같은 대체 문구를 쓰지 않는다. 상태는 색과 텍스트를 함께 쓴다. LOT 번호는 **저장된 번호를 그대로** 보인다. 구분자(자재 LOT의 「|」)를 바꾸거나 없는 구분자를 넣지 않고, 다른 기호로 끊어 보이지 않는다. 화면 글자가 라벨, 스캔값과 같아야 눈으로 대조할 수 있고 복사해 검색할 수 있기 때문이다. 표에서는 고정폭 글꼴로 한 줄에 보이고, 대조에 쓰이므로 말줄임하지 않는다(C-16 예외).

### C-11 셸 공통 틀

**기준.** 머리줄과 하단 동작 바는 **화면이 조립하지 않는다.** POP와 모바일은 셸이 제공하고, 관리웹은 공용 부품(`ProcessPage`, `ActionBar`, `DetailDrawer`)이 제공한다. 화면은 제목, 상태, 동작만 넘긴다. POP 머리줄 항목은 스테이션명, 작업자, 현재 W/O와 공정, 통신 상태로 고정한다. 단말은 내부 번호가 아니라 단말 코드로 표시한다.

### C-12 입력 장치

**기준.** 날짜는 DS `DatePicker` 하나(형식 yyyy-MM-dd, 타이핑과 달력 모두 허용). 일시는 공용 부품 `DateTimeField`(DatePicker와 24시간제 시각 글자 칸 HH:mm의 조합. 브라우저 시각 입력은 언어 설정에 따라 「AM/PM」으로 보여 쓰지 않는다)를 쓴다. 브라우저 기본 `type="date"`, `type="datetime-local"`, `type="time"`을 화면에서 직접 쓰지 않는다(예외 없음). 숫자 키패드는 DS `NumberPad` 하나, 지우기 문구는 [전체 지움]으로 통일한다.

**가끔 쓰는 숫자 입력은 창으로 연다.** 사번처럼 화면에서 한 번 넣고 마는 값은 키패드를 화면에 펼쳐 두지 않고, 버튼(예: [사번 입력])으로 여는 창에 둔다. 같은 값을 넣는 자리(정 작업자, 부 작업자)는 같은 창을 쓴다. 창이 열리면 입력 칸에 포커스를 두어 키보드와 스캐너 입력을 바로 받고, Enter는 확인으로 처리한다. 수량처럼 작업 내내 반복해 넣는 값은 이 규칙의 대상이 아니다(사용자 화면 확인 결정, 2026-10-23).

**선택 입력은 목록의 성격으로 고른다. 건수로 고르지 않는다.** 개발 시점의 건수는 운영 중에 늘어나기 때문이다.

| 목록의 성격                                                          | 예                                                                                           | 입력 방식                                                      |
| -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 기준 정보 참조(운영 중 늘어나는 마스터)                              | 품목, 거래처(공급사, 고객), 창고, 적치 위치, 생산 라인, 설비, 금형과 툴, 작업자, 사용자, W/O | **참조 선택 팝업**(`ReferenceField`와 `PickerDialog`)          |
| 고정 코드 목록(코드 사전, 업무 중 늘지 않음, 20건 이하)              | 상태, 유형, 판정, 사유 코드                                                                  | DS `Select`                                                    |
| 두세 개 중 하나                                                      | 일상과 정기, 전체와 일부                                                                     | `Radio` 또는 세그먼트                                          |
| 조직과 운영 단위(공장마다 정해진 설정, 업무 중 늘지 않음, 20건 이하) | 사업부, 공장, 교대                                                                           | DS `Select`. 값이 하나뿐이면 칸을 두지 않고 머리 요약에 보인다 |
| 한 대상에 딸린 짧은 목록                                             | 품목 하나의 BOM, Routing 개정                                                                | DS `Select`                                                    |

**기간 입력.** 기간(납기 기간, 조회 기간)은 DS `DatePicker`의 기간 모드를 쓴다. 칸이 비었을 때 「시작일 ~ 종료일」을 보이고, 달력 안에서 지금 고를 날짜(시작일, 종료일)를 알린다. 시작일만 고르고 닫으면 버리지 않고 「시작일부터」로 적용하고 칸에 「2026-10-01 ~」로 보인다. 이 동작이 DS에 없으면 DS 요청을 내고, 그동안 화면 감싸개에서 처리한다. 칸 폭은 C-19의 「보통」 이상이다.

참조 선택 팝업의 구성은 기존 공용 품목 선택 창(`patterns/item-picker`, IQC 수입검사의 품목 조건이 사용)을 기준으로 한다.

- **입력칸(`ReferenceField`)**: 읽기 전용 검색 칸. 누르거나 Enter를 치면 팝업이 열린다(`aria-haspopup="dialog"`). 선택 후에는 「이름 (코드)」를 표시하고(C-10), 값이 있을 때만 칸 안 ×로 지운다. 주소나 저장된 값으로 들어온 번호도 이름으로 풀어 표시한다. 내부 번호를 직접 입력받지 않는다.
- **팝업(`PickerDialog`)**: 위에서 아래로 검색어와 분류 필터 한 줄과 [찾기](Enter로도 검색), 결과 표, 페이지 이동, 하단 [취소]와 [〈동작〉]. 검색어가 비면 분류의 전체를 보인다. 결과 표는 행 전체 클릭(C-1)으로 고르고, 여러 건을 고르는 팝업만 체크박스를 쓴다. 쪽을 넘겨도 고른 항목을 유지한다. 사용 중지된 항목은 기본으로 제외하고, 조회 조건처럼 지난 자료를 찾는 칸에서만 포함한다. 결과가 0건이면 좁힌 조건을 함께 알린다.
- **의존 관계**: 다른 값에 따라 범위가 정해지는 참조(창고에 따른 위치)는 앞 값으로 팝업 범위를 좁혀 연다. 앞 값이 비어 있으면 팝업에서 상위 값(창고)도 고를 수 있게 하고, 위치를 고르면 창고도 함께 채운다. 앞 값을 바꾸면 뒤 값을 비우고 「남은 일」로 알린다. 화면에 앞 값 칸이 없으면(W/O 기본 위치에 창고 칸이 없음) 팝업의 분류 필터로 범위를 좁혀 연다(예: 완제품 위치는 제품 창고 분류).
- **추천**: 기준 정보로 정해지는 추천 값(적치 규칙의 위치)이 있으면 팝업 결과 맨 위에 「추천」 표시로 두고, 입력칸 옆 [추천 적용]으로 팝업 없이 바로 채울 수도 있게 한다.
- POP는 같은 역할의 `PopSelect` 팝업을 쓰고, 모바일은 스캔을 먼저 두고 팝업을 보조로 둔다.

### C-13 문구

**기준.** 화면 문구는 사용자가 할 수 있는 일만 말한다. 개발 사정(「아직 확정되지 않은 임시 목록」, 「서버가 아직 지원하지 않습니다」, 「응답에 … 담기지 않았습니다」, 「화면은 이 값을 해석하지 않고」)과 내부 식별자를 노출하지 않는다. 코드값(`POSTED`, `MATERIAL`)은 코드 사전의 이름으로 바꿔 보인다. 라벨, 구획 제목, 단계 이름은 명사형. 안내와 오류는 무엇이 안 됐는지와 할 일을 한두 문장으로 쓴다.

- 라벨, 머리글, 버튼, 탭, 단계 이름, **화면 이름과 메뉴 이름**에 가운뎃점(`·`)으로 여러 항목을 잇지 않는다. 여러 대상으로 검색하는 칸은 라벨을 「번호 검색」, 「검색어」처럼 하나로 두고, 대상은 안내 문구(placeholder)에 「입하번호 또는 거래명세서번호」로 적는다. 두 항목을 꼭 함께 써야 하면 「와/과」, 「및」, 쉼표를 쓴다.
- **화면 이름 짓기.** 화면이 하는 대표 업무 하나로 짓는다(함께 하는 조회, 취소, 재출력은 화면 안의 동작). 대상이 둘 이상이면 상위 명사로 묶거나 「와/과」, 쉼표로 잇는다. 괄호 부연을 붙이지 않는다. 명사형, 한글 12자 내외로 사이드바에서 말줄임되지 않게 한다. 업무 용어(IQC, W/O, Lot Status)는 유지한다. 화면 이름과 메뉴 이름은 이 원칙으로 클라이언트가 정한다. 화면을 고칠 때 그 화면 이름도 원칙에 맞춘다.
- **선택지와 버튼 이름은 실제 대상 이름으로 쓴다.** 「이 설비」, 「해당 공정」처럼 가리키는 말을 쓰지 않고 「사출기 1호기」처럼 데이터의 이름을 쓴다. 머리줄이나 다른 영역의 이름과 바로 대조할 수 있어야 한다(사용자 화면 확인 결정, 2026-10-23).
- **화면 용어는 일반 MES 용어를 먼저 쓴다.** 같은 뜻의 말은 화면마다 같게 쓰고, 정한 용어는 아래 「화면 용어집」에 모은다. 새 말을 만들기 전에 용어집과 일반 MES 용어(불출, 투입, 잔량, 실적 등)를 먼저 찾는다(사용자 화면 확인 결정, 2026-10-26).
- 화면 문구에 영어 낱말을 쓰지 않는다. 업무에서 영어로 굳어진 용어(W/O, ERP, BOM, Routing, LOT, Lot Status, IQC, Location, Release, Hold, Import 등)와 고유 명칭만 예외이고, 목록은 정적 검사의 `BUSINESS_TERMS`에 둔다. 4M 분류는 「설비, 작업자, 금형, 위치」, 「Validation」은 「점검」으로 쓴다.
- 서버가 준 문구(점검 지적, 오류)에 내부 번호(「설비(1)」)가 있으면 화면이 아는 이름 「이름 (코드)」으로 바꾸고, 모르면 번호를 지운다. 서버가 이름을 싣도록 C-15로 요청한다.
- 확인 창과 안내에 화면 처리 방식이나 데이터 구조를 설명하지 않는다(예: 「공정 간 의존 관계가 생성됩니다」). 사용자가 보는 결과(「W/O 3건 생성: 사출 성형, 조립, 포장」)로 쓴다.
- 화면 구성을 바꾸는 작업에서는 그 화면의 **기존 문구 전체**에 이 규칙을 적용한다. 「구성만 바꾼다」는 문구를 그대로 두라는 뜻이 아니다.

### C-16 표 셀은 한 줄

**기준.** 표는 한 화면에 최대한 많은 행과 열이 보이게 한다. 그래서 **표 셀의 텍스트는 줄바꿈하지 않는다**(머리글 포함).

- 열 폭은 내용 길이로 정한다. 코드, 번호, 수량, 일시, 상태 칩 열은 내용만큼, 이름이나 설명처럼 긴 텍스트 열 **하나**가 남는 폭을 가져간다.
- 남는 폭보다 긴 텍스트는 말줄임(…)으로 자르고(대조에 쓰는 LOT 번호와 문서 번호는 제외, C-10), 전체 값은 툴팁(`title`)과 상세(드로어, 처리 화면)에서 보인다.
- 두 값을 한 셀에 쌓지 않는다(위아래 두 줄). 코드와 이름은 열을 나눈다(C-10). 그 밖의 두 값은 열을 나누는 것이 기본이다.
- 셀에 설명 문장을 넣지 않는다. 상태와 사유는 상태 칩으로 표시한다(C-4).
- 1280×800에서 가로 스크롤이 생기면 우선순위가 낮은 열을 상세로 옮긴다. 열을 줄이기 전에 줄바꿈으로 버티지 않는다.
- 표 밀도는 DS `Table`의 `density="compact"`를 기본으로 한다.

- 일괄 동작 결과 칩(C-18)은 새 열을 만들지 않고, 결과가 보이는 동안 「처리 상태」 칸의 상태 칩 **자리에** 보인다. 결과를 닫으면 상태 칩으로 돌아간다. 실행 전후로 열 수와 칸 폭이 같아야 표가 흔들리지 않는다.
- 조건으로 이미 같은 값만 보이는 열(「확인 필요」 조건의 처리 상태)은 숨기지 않는다. 다만 그 열의 칩은 조건 칩과 같은 이름과 색이어야 한다(C-17).
- **가로 넘침 금지.** 1280×800에서 판단에 쓰는 열과 행 동작(버튼, 입력 칸)이 가로 스크롤 밖에 있으면 안 된다. 입력 칸이 있는 편집 표는 한 행의 입력 칸을 4개 이하로 두고, 나머지는 행을 눌러 여는 편집 영역(처리 화면의 2단, 마스터형의 편집 패널)으로 옮긴다. 행 동작은 C-1의 오른쪽 고정 열에 둔다.

**이탈 조건.** 사용자가 입력하는 긴 텍스트(비고, 의견)를 그대로 읽어야 하는 이력 표는 그 열만 두 줄까지 허용하고 넘치면 말줄임한다.

### C-15 규칙이 요구하는 정보와 결정의 추가

규칙이 요구하는 정보(처리 대기 수, 판정, 추천 위치 등)나 결정(자동값 규칙 등)이 서버 계약과 업무 이슈에 없을 때의 기준이다. **숨기는 것으로 대신하지 않고 추가를 요청한다.** 다만 아무 정보나 늘리지 않도록 먼저 필요성을 판단한다.

**판단 기준.** 다음 네 가지를 모두 만족해야 추가할 정보다.

| 기준           | 질문                                                                                             | 만족하지 않는 예                                   |
| -------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| 판단에 쓰임    | 사용자가 이 화면에서 무엇을 먼저 할지, 처리할 수 있는지, 결과가 맞는지 판단하는 데 직접 쓰이는가 | 등록자 연락처, 생성 일시처럼 처리 판단과 무관한 값 |
| 다른 화면 의존 | 이 정보가 없으면 사용자가 다른 화면을 열어 확인해야 하는가                                       | 같은 화면의 다른 영역에 이미 보이는 값             |
| 업무 데이터    | 이미 있는 업무 데이터로 정해지는 값인가(새 업무 규칙을 만들지 않는가)                            | 화면이 임의로 정한 우선순위, 점수                  |
| 대체 불가      | 이미 있는 표시로 같은 판단을 할 수 없는가                                                        | 상태 칩으로 이미 알 수 있는 「처리 가능 여부」     |

**절차.**

1. 판단 기준 넷을 구성안 표에 적는다. 하나라도 만족하지 않으면 추가하지 않고, 규칙의 해당 요소를 이탈로 기록한다.
2. 이미 받는 응답으로 계산할 수 있으면 화면에서 계산한다. 행 수와 관계없이 횟수가 정해진 목록 호출(예: 배포 전 W/O 목록 한 번, 업무 번호를 검색어로 한 목록 조회 한 번)은 「이미 받는 응답」에 포함한다. 목록 행 수만큼 추가 호출이 필요하면(행마다 상세 조회) 계산하지 않고 3으로 간다. 사용자가 체크한 건에 대해 실행 직전에 부르는 조회(일괄 동작 예고)는 허용한다. 체크가 많아 1초 이상 걸리면 확인 창에 진행 표시를 둔다. 계약 값이 실제 동작과 다르면(필터 결과와 실행 결과가 다름) 그 값을 쓰지 않고 3으로 간다.
3. 계산할 수 없으면 요청한다. 데이터와 API, 서버 결함은 서버 이슈(omf-mes-server), 업무 결정은 해당 업무 이슈(omf-all-around)에 글로 적는다(머리말 「공개 범위」, 캡처 첨부 금지). 요청에는 필요한 정보, 사용 위치(화면과 영역), 판단 기준 넷의 답, 대체 표시가 없는 이유를 적는다. 작성 초안은 `.client-dev/requests/`에 둔다(커밋하지 않음).
4. 회신 전까지 그 항목은 작업 이슈에 「계약 대기」로 기록하고 화면의 완료 조건에 포함한다. 화면에 가짜 값, 빈 자리, 「준비 중」 표시를 두지 않는다. 사용자가 부분 반영을 승인한 경우에만 그 항목 없이 완료 보고를 할 수 있고, 보고에 승인 사실과 대기 항목을 적는다.

**예.** 처리형 작업함의 처리 대기 수와 판정 구성은 네 기준을 모두 만족한다(어느 건부터 처리할지 판단, 없으면 전표를 하나씩 열어야 함, 입하 라인과 판정 데이터로 정해짐, 다른 표시로 대체 불가). 입하 담당자 이름은 처리 판단에 쓰이지 않으므로 추가하지 않는다.

### C-17 자동 처리 결과 검토

서버가 사람 대신 값을 채우거나 다음 단계까지 진행하는 업무(오더 수신 시 계획 자동 작성과 전개, 설비와 금형 자동 배정 등)의 화면 기준이다. 사람이 할 일은 **자동으로 끝나지 못한 건을 찾아 고치는 것**이므로, 화면은 예외를 먼저 보여 주고 정상 건은 한꺼번에 넘기게 한다.

**작업함.**

- 작업함의 **조건, 머리 건수, 행 상태 칩은 같은 기준**이다. 한 화면에서 조건은 「자동 계획 완료」인데 행 칩은 「확인 필요」인 상태를 만들지 않는다. 서버가 그 기준으로 거르고 셀 수 없으면 C-15로 요청하고, 그동안은 셋 다 서버 기준(자동 처리 결과)으로 두고 다음 단계를 막는 사유만 사유 칩으로 보인다. 이 잠정 기간에는 이름도 서버 기준의 뜻대로 쓴다(「자동 계획 완료」, 「배포 가능」으로 부르지 않는다). 행 칩은 조건과 같은 상태이거나, 화면이 정해진 횟수의 호출로 계산할 수 있는 **다음 상태**(배포 대기 0건이면 「배포 완료」)만 보인다. 조건과 반대되는 상태(조건 「자동 계획 완료」 안의 「확인 필요」)는 보이지 않는다.
- 자동 처리 상태는 **다음 단계로 넘길 수 있는가**로 나눈다. 「자동 처리를 실행했는가」가 아니다. 이름은 **다음에 할 일**로 짓는다. 다음 단계가 가능하면 「〈다음 단계〉 가능」(예: 배포 가능), 사람이 고쳐야 하면 「확인 필요」, 아직 시도하지 않았으면 「자동 〈처리〉 전」, 끝났으면 「〈다음 단계〉 완료」(예: 배포 완료).
- 자동 처리가 끝났어도 다음 단계가 막혀 있으면(배포에 필요한 위치 미설정 등) 「완료」로 보이지 않는다. 그 건은 「확인 필요」와 막힌 사유로 보인다. 다음 단계의 가능 여부를 판정할 데이터가 목록 응답에 없으면 C-15로 요청한다.
- 서버 사유에 없는 막힘(예: 작성 중 계획의 라인 미정)은 처리 화면 머리에서만 데이터로 더하고, 목록에는 서버가 사유로 줄 때까지 더하지 않는다(C-15 2). 서버에 사유 추가를 요청한다.
- 「확인 필요」 건은 **사유를 목록에 칩으로** 보인다(예: BOM 없음, 라인 미정). 사유가 여럿이면 첫 사유와 「외 N」. 사유 문장을 셀에 쓰지 않는다(C-16).
- 기본 조회 조건은 「확인 필요」다. 페이지 머리에 상태별 건수(확인 필요 N, 자동 처리 완료 N)를 보이고, 누르면 그 조건으로 바뀐다.
- 「자동 처리 완료」 건의 다음 단계(배포 등)는 작업함의 일괄 동작으로 한다(C-18). 하나씩 열어 확인하게 만들지 않는다.
- 자동 처리를 다시 시도하는 동작(기준정보를 고친 뒤 재실행)은 처리 화면의 동작과 작업함의 일괄 동작 두 곳에 둔다.

**처리 화면.**

- 「확인 필요」 건을 열면 **사유가 가리키는 단계**로 바로 연다(라인 미정이면 계획 단계, 위치 미설정이면 4M 단계). 사유와 단계의 대응은 구성안 표에 적는다.
- 「자동」 표시는 서버가 준 출처(배정 출처 칸)로만 붙인다. 추천 응답과 값이 같다는 것으로 추정하지 않는다. 출처 칸이 없으면 C-15로 요청하고 그동안 표시를 두지 않는다.
- 자동으로 채운 값은 입력 칸에 그대로 두되 「자동」 표시와 출처(기준정보 이름)를 보인다(예: 설비 칸에 「사출기 1호기 (EQ-INJ01)」, 옆에 「자동」 칩, 툴팁에 「품목 설비 매핑의 기본값」). 사람이 바꾼 값은 표시를 지운다.
- 사용자가 화면에서 고칠 수 없는 사유(ERP에서 받는 BOM 없음 등)는 「남은 일」에 C-5의 「해결할 수 없음」 문형으로 담당과 할 일을 말하고, 고칠 곳이 다른 화면이면 그 화면으로 가는 링크를 둔다.

**이탈 조건.** 자동 처리 결과가 한 종류뿐이고(실패가 없는 계산) 사람이 검토할 일이 없으면 작업함 상태를 두지 않는다.

### C-18 일괄 동작 결과

여러 건에 한 번에 실행하는 동작(일괄 배포, 일괄 재실행, 일괄 승인)의 기준이다.

- **집계 단위.** 결과는 목록 행 단위(예: ERP W/O)로 세고, 행 아래 항목이 일부만 처리되면 「일부 처리」로 센다. 첫 줄은 「처리 N건, 일부 처리 N건, 건너뜀 N건, 실패 N건」이고, 항목 단위 수(예: W/O 5건 배포)를 함께 보인다.
- **예고와 실행은 같은 판정을 쓴다.** 실행 전 확인의 건너뜀 예고는 실행 결과와 같은 기준으로 계산한다. 모든 대상이 건너뛸 것이면 실행 버튼을 잠그고 그 이유를 적는다.
- **실행 전 확인.** 대화상자에 대상 건수, 「〈동작〉 시 반영 사항」(명사형 목록), 건너뛰는 조건을 보인다. 체크한 건 중 이미 건너뛸 것으로 판정할 수 있는 건은 실행 전에 그 수를 알린다(예: 3건 중 1건은 위치 미설정으로 건너뜀).
- **결과 요약.** 실행 후 목록 위에 결과 영역을 둔다. 첫 줄은 「처리 N건, 건너뜀 N건, 실패 N건」. 토스트만으로 끝내지 않는다. 사용자가 닫거나 다시 조회할 때까지 남긴다. 모두 처리되면 성공 표시, 건너뜀이나 실패가 있으면 경고 표시를 쓰고, 실패만 오류 색을 쓴다.
- **건별 결과는 목록 행에.** 이번 실행 대상이었던 행에 결과 칩(처리, 건너뜀, 실패)을 붙이고, 결과 영역의 [건너뜀만 보기], [실패만 보기]로 목록을 좁힌다. 건별 사유는 결과 칩의 툴팁과 결과 영역 목록에 짧게 쓴다.
- **고칠 곳으로 연결.** 건너뜀과 실패 건은 행을 누르면 처리 화면의 해당 단계로 간다(C-17). 결과 영역의 건별 줄에도 같은 링크를 둔다.
- 처리된 건은 다음 조회에서 목록 조건에 따라 빠질 수 있다. 결과 영역은 빠진 건도 건수에 포함한다.

### C-19 시각 기준

값은 디자인 시스템 토큰과 배치 클래스(`layout-conventions.md` 「배치 클래스 목록」)로만 정한다. 화면 CSS에 글자 크기, 칸 폭, 버튼 높이를 숫자로 적지 않는다.

**제목 단계.** 한 화면의 제목은 세 단계다. 아래 단계 제목이 위 단계보다 크거나 굵으면 안 된다.

| 단계 | 자리                                                      | 토큰                                         |
| ---- | --------------------------------------------------------- | -------------------------------------------- |
| 1    | 화면 제목. 작업함 제목과 처리 화면 제목(대상 번호)이 같다 | `--type-headline-lg` (28/36, 700)            |
| 2    | 구획 제목(조회 조건 제외), 단계 본문 제목, 확인 창 제목   | `--type-title-lg` (20/28, 500)               |
| 3    | 구획 안 소제목(편집 영역의 묶음, 반영 사항 머리)          | `--type-title-sm` (16/24, 500)               |
| 라벨 | 입력 칸 라벨, 표 머리                                     | `--type-label-sm`, 표 머리는 DS `Table` 기본 |
| 본문 | 표 셀, 안내 문장, 하단 바 「남은 일」                     | `--type-body-sm` (14/20)                     |

- 상자 안에 상자를 넣지 않는다(구획 상자 1겹). 묶음은 소제목과 간격(`--space-6`)으로 나눈다.
- **소제목 위치.** 소제목(3단계)은 묶음 **위에** 한 줄로 둔다. 칸 왼쪽에 제목 열을 두는 배치(왼쪽 제목, 오른쪽 칸)는 쓰지 않는다. 제목 열이 칸 폭을 빼앗고, 좁은 제목 열에서 제목이 두 줄로 접히기 때문이다.
- **제목과 라벨은 한 줄.** 구획 제목, 소제목, 입력 칸 라벨, 단계 이름은 줄바꿈하지 않는다. 접히면 배치를 바꾼다(소제목을 위로, 열 수 조정). 줄여 쓰는 것으로 맞추지 않는다.
- 대상 번호, W/O 번호, LOT 번호는 고정폭 글꼴을 쓰되 글자 크기는 그 자리의 단계를 따른다.

**조회 조건 칸 폭.** 칸 폭은 세 가지 중 하나이고 배치 클래스 `filter-field-sm`, `filter-field-md`, `filter-field-lg`로 준다(배치 규범에 추가 제안). 칸 사이 간격은 `--space-3` 하나다.

| 폭   | 값    | 쓰는 칸                                    |
| ---- | ----- | ------------------------------------------ |
| 좁음 | 160px | 고정 코드 Select, 날짜 하나                |
| 보통 | 240px | 번호 검색, 참조 선택(ReferenceField), 기간 |
| 넓음 | 320px | 여러 번호를 받는 검색                      |

- 칸 폭은 고른 값에 따라 바뀌지 않는다. 값이 길면 말줄임하고 툴팁으로 보인다.
- [초기화] [조회]는 줄 오른쪽 끝에 둔다(배치 규범 2).

**표.** 셀은 세로 가운데 정렬이다. 머리 배경은 모든 열이 같다(행 동작 열 포함, 동작 열 머리는 화면에서 비우되 접근 이름은 둔다). 합계 행은 표 전체 폭을 쓴다.

**버튼.** 높이는 두 가지다. 영역의 동작(페이지 머리, 조회 조건, 하단 바, 확인 창)은 `--control-height-md`, 표 행과 결과 영역 안 동작은 `--control-height-sm`. 모양은 역할로 정한다. 주 동작은 채움, 보조 동작은 테두리, 글자 버튼은 문장 안의 이동 링크와 처리 머리의 [← 〈작업함〉]에만 쓴다. 같은 영역 안 버튼은 같은 높이다. 값을 넣는 칸을 버튼(「입력」)으로 대신하지 않는다. 칸을 두거나 「추가 입력(선택)」으로 접는다.

**색.** 빨강(주 색)은 주 동작과 이상 상태에만 쓴다. 단계 표시의 완료 단계는 중립 색 이름과 체크 표시이고, 누를 수 있다는 것은 마우스를 올렸을 때 밑줄로 알린다. 상태 칩 색은 상태 하나에 색 하나다(확인 필요 경고, 가능 성공, 완료 정보, 전 중립). 조건 칩(머리 건수)은 선택 여부와 관계없이 같은 모양이고 선택된 것만 테두리를 굵게 한다.

**안내 상자.** 한 구획에 하나까지, 두 줄 이내. 좁은 칸(편집 영역의 열) 안에 두지 않고 구획 맨 위 전체 폭에 둔다. 칸 하나에 대한 설명은 라벨 옆 ⓘ 툴팁으로 둔다.

### C-20 기존 부품을 재사용할 때

화면 구성을 바꾸면서 기존 화면의 부품(편집기, 표, 찾기 창)을 단계 안에 넣을 때, **업무 로직(조회, 저장, 검증 호출)만 재사용하고 표시는 이 규범대로 바꾼다.** 넣은 부품이 다음을 지키는지 하나씩 점검하고 구성안 표에 결과를 적는다.

| 점검                                                                | 규칙       |
| ------------------------------------------------------------------- | ---------- |
| 입력 장치: 날짜와 일시, 참조 선택 팝업, 끝 열 [선택] 없음           | C-12, C-1  |
| 버튼 위치와 모양: 채움 버튼은 하단 바 하나, 부품 안 [저장]은 테두리 | C-3, C-19  |
| 제목 단계와 상자 겹침                                               | C-19       |
| 문구: 가운뎃점, 영어, 코드값, 「이름 (코드)」                       | C-10, C-13 |
| 높이: 단계 본문이 1280×800 안                                       | C-14       |
| 안내 상자 수와 위치                                                 | C-19       |

부품을 고치면 그 부품을 쓰는 다른 화면도 같이 바뀐다. 다른 화면에 영향이 있으면 구성안에 적고 그 화면도 같은 검사로 확인한다. 바꿀 수 없는 사정(계약 대기 등)이 있으면 항목별로 이탈을 기록한다.

### C-21 현장 화면의 정보와 이름 (POP, 모바일)

현장 작업자는 서서, 짧게 보고, 다음 동작을 한다. 화면의 값 하나하나가 **지금 할 일의 어떤 판단에 쓰이는지** 말할 수 없으면 두지 않는다(사용자 화면 확인 결정, 2026-10-23, 자재 투입).

- **대상은 이름으로 알아본다.** 목록 줄과 편집 영역의 첫 줄은 사람이 읽는 이름(품목명)이다. 번호(LOT 번호, W/O 번호)는 라벨과 대조하는 값이므로 그 아래 한 줄로 둔다. 같은 번호를 한 화면에 여러 번 쓰지 않는다(목록 줄, 편집 영역 머리, 결과 안내에 같은 LOT 번호 반복 금지). 코드는 이름 옆 「이름 (코드)」로 충분하면 따로 줄을 두지 않는다.
- **수량은 「진행 / 기준」 하나로 보인다.** 불출량과 투입량처럼 기준과 진행이 있는 값은 「투입량 30 / 100 KG」(투입량 / 불출량)처럼 한 쌍으로 쓰고 옆에 진행 막대를 둔다. 잔량은 지금 넣을 칸(편집 영역)처럼 그 값으로 할 일이 있는 자리에만 「잔량 70 KG」으로 둔다. 화살표로 셋 이상을 잇지 않는다. 「차이」, 「누계」처럼 무엇과 무엇의 차이인지, 무엇의 합인지 이름만으로 알 수 없는 말은 쓰지 않는다(사용자 화면 확인 결정, 2026-10-26).
- **음수를 보이지 않는다.** 기준을 넘으면 「-5 KG」 대신 「과투입 5 KG」 예외 칩으로 알리고, 진행 막대는 가득 찬 채 경고 색으로 바꾼다.
- **끝난 항목은 끝났다고 보인다.** 기준에 닿은 줄은 상태 칩 「투입 완료」(넘쳤으면 「과투입 N」 칩)를 달고, 진행 중인 줄과 한눈에 구분되게 한다(C-17 상태 이름은 다음 할 일 기준). 할 일이 남은 줄을 위에, 끝난 줄을 아래에 둔다(투입 중, 미투입, 과투입, 투입 완료 순, 같은 묶음 안은 원래 순서). 다시 정렬은 화면을 열 때와 다음 대상을 스캔할 때만 한다. 방금 끝낸 줄은 그 자리에 두어 눈앞에서 사라지지 않게 한다. 목록 위에 「투입할 자재 N건, 투입 완료 N건」을 한 줄로 보인다(사용자 화면 확인 결정, 2026-10-26).
- **앞 단계의 값은 이 화면의 할 일이 아니면 두지 않는다.** 출고 수량, 출고와 수령의 차이처럼 다른 담당의 일은 예외일 때만(덜 받음, 못 받음) 칩 하나로 알린다.
- **정상은 표시하지 않고 예외만 보인다.** LOT 상태 「정상」, 「수령 완료」처럼 늘 같은 값은 두지 않는다. 보류, 부족, 미수령처럼 할 일이 생기는 상태만 칩으로 보이고, 칩 이름은 그 상태에서 할 일이 보이게 짓는다(C-17).
- **목록 줄은 제목과 정보를 나눈다.** 한 줄(카드)의 맨 위는 제목 줄이다: 대상 이름(굵게)과 오른쪽 끝의 상태 칩. 그 아래 정보 영역은 「라벨 값」 쌍을 같은 열에 맞춰 둔다(예: 「LOT …0008」, 「투입량 30 / 100 KG」). 제목 줄과 정보 영역 사이는 간격(`--space-2` 이상)이나 구분선으로 나눠, 값이 제목에 붙어 읽히지 않게 한다. 라벨 없는 값을 문장처럼 이어 쓰지 않는다(사용자 화면 확인 결정, 2026-10-26).
- **목록 줄의 상태는 하나.** 한 줄에 상태 칩은 하나이고, 그 줄의 진행(미투입, 투입 중, 투입 완료)을 말한다. 같은 뜻을 칩과 글자로 두 번 쓰지 않는다.
- **영역 제목은 내용을 그대로 말한다.** 정보와 입력이 함께 있는 영역은 제목을 그 대상으로 짓는다(예: 고른 품목 이름). 입력 칸 묶음은 소제목으로 정보와 나눈다(C-19).
- **결과 안내는 한 줄로 짧게.** 스캔과 기록 결과는 대상 이름과 결과만 말한다(「ABS 수지를 담았습니다」). 다음 결과가 오거나 다음 동작을 하면 지운다.

## 7. 배치 규범 5 개정 제안

현행 규범 5는 창 폭 1280px 이하에서 2단을 1단으로 접는다. 사이드바를 펼친 1280×800 노트북에서는 이 때문에 옆에 열리던 상세가 목록 아래로 내려가고, 실측에서 선택 결과가 아래에 쌓이는 관리웹 화면이 12개에서 24개로 늘었다.

**제안.** 마스터형의 2단은 왼쪽 목록 최소 폭 280px, 오른쪽 나머지로 두고 접힘 기준을 **본문 폭 900px**(창 폭 약 1160px)로 낮춘다. 오른쪽 패널의 폼 2열은 패널 폭 680px 미만에서 1열로 접는다(컨테이너 쿼리). 조회형은 드로어를 쓰므로 접힘 기준이 필요 없다.

| C-13 문구                        | 정적 C-13(개발 사정 표현, 가운뎃점, 영어 낱말), 실측 P-13(내부 번호)                                                                                        | 코드값을 이름으로, 처리 방식 설명 금지, 화면 이름                 |
| C-14 크기 검증                   | 실측 전체(검증 크기에서 실행)                                                                                                                               | POP, 모바일 크기                                                  |
| C-15 정보 추가                   | 없음                                                                                                                                                        | 구성안의 판단 기준 넷과 요청                                      |
| C-16 표 셀                       | 실측 P-6, P-7                                                                                                                                               | 결과 칩 자리, 열 우선순위                                         |
| C-17 자동 처리 결과              | 없음                                                                                                                                                        | 조건, 건수, 행 칩의 같은 기준, 상태 이름                          |
| C-18 일괄 동작 결과              | 없음                                                                                                                                                        | 예고와 실행의 같은 판정, 일부 처리 집계                           |
| C-19 시각 기준                   | 실측 P-8(상자 안 상자 1겹부터), P-9, P-11, P-12, P-14(제목과 라벨 줄바꿈), 정적 TOKEN(fallback이 있어도 미정의 토큰은 위반), COLOR(CSS와 tsx 인라인 스타일) | 버튼 모양과 높이, 안내 상자 수, 색                                |
| C-20 재사용 부품                 | 위 검사가 부품에도 적용                                                                                                                                     | 구성안의 C-20 표                                                  |
| C-21 현장 화면의 정보            | 없음                                                                                                                                                        | 값마다 쓰이는 판단, 이름 우선, 번호 반복, 수량 이름, 정상 값 숨김 |
| T-W-C 처리형                     | 실측 P-3, P-4, P-15(단계 본문 넘침)                                                                                                                         | 단계, 하단 바, 중간 확정, 저장 안 한 변경, 지난 단계 요약 형식    |

- 「자동」이 없는 규칙을 바꾸거나 새로 만들 때는 검사 항목을 함께 만들 수 있는지 먼저 본다. 만들 수 없으면 점검표 문장을 구체적으로 쓴다.
- 검사 도구의 판정 불가(데이터 없음)는 통과가 아니다. 완료 보고에 판정 불가 경로와 이유를 적는다.

## 9. 점검표

화면을 만들거나 고친 뒤 완료 보고 전에 확인한다. 검사 스크립트가 잡는 항목은 (자동)으로 표시했다.

- [ ] 유형을 판정하고 화면 파일 머리 주석에 유형 번호(T-…)를 적었다
- [ ] 행 전체 클릭으로 선택된다. 끝 열 [선택] 버튼이 없다 (자동)
- [ ] 선택 결과가 목록 아래에 추가되지 않는다
- [ ] 영역마다 채움 버튼이 하나이고 유형별 위치에 있다
- [ ] 비활성 주 동작에 「남은 일」이나 사유가 보이고 `aria-describedby`로 이어진다 (자동)
- [ ] 「준비 중」 버튼과 늘 잠긴 칸이 없다
- [ ] 두 단계 이상이면 단계 표시와 「남은 일」이 있다
- [ ] 처음 열었을 때 오류가 표시되지 않는다
- [ ] 날짜는 `DatePicker`, 페이지 이동은 공용 부품을 쓴다 (자동)
- [ ] 기준 정보 참조(품목, 거래처, 창고, 위치, 설비, 작업자 등)는 `Select`가 아니라 참조 선택 팝업을 쓴다
- [ ] 화면 폴더에 공용 부품의 복제본을 새로 만들지 않았다 (자동)
- [ ] DS에 없는 토큰과 직접 지정한 색을 쓰지 않았다 (자동)
- [ ] 검증 크기에서 주 동작과 선택 컨트롤이 스크롤 없이 보인다 (자동: 화면 실측 검사)
- [ ] 표 셀이 한 줄이다. 긴 텍스트는 말줄임과 툴팁, 셀에 설명 문장 없음 (자동: 화면 실측 검사 P-6)
- [ ] 선택할 수 없는 행에 상태 칩과 같은 뜻의 안내 문장을 중복으로 두지 않았다
- [ ] 기준 정보는 표에서 코드 열과 이름 열로 나누고, 한 줄 안에서는 「이름 (코드)」로 표시했다
- [ ] 문구가 C-13을 따른다. 고친 화면의 기존 문구와 코드값 표시도 확인했다
- [ ] 규칙이 요구하는 정보가 없을 때 C-15 판단 기준을 적었고, 필요한 정보는 요청서를 냈다
- [ ] 처리형: 확인 단계의 반영 사항이 1280×800 첫 화면 안에 있고, 완료 후 다음 처리 대상 버튼이 있다
- [ ] 표가 1280×800에서 가로로 넘치지 않는다. 판단에 쓰는 열과 행 동작이 보인다 (자동: 화면 실측 검사 P-7)
- [ ] 메뉴 없이 앞 화면 버튼으로만 들어가는 후속 화면을 새로 만들지 않았다. 같은 업무의 다음 단계는 처리 화면의 단계다
- [ ] 자동 처리 업무: 작업함 기본 조건이 「확인 필요」이고, 사유가 목록 칩으로 보이며, 「완료」는 다음 단계 가능을 뜻한다
- [ ] 일괄 동작: 결과 요약이 목록 위에 남고, 건별 결과가 행에 붙고, 건너뜀과 실패 건에서 고칠 곳으로 갈 수 있다
- [ ] 일괄 동작: 실행 전 건너뜀 예고와 실행 결과가 같은 판정이고, 일부 처리를 따로 센다
- [ ] 작업함의 조건, 머리 건수, 행 상태 칩이 같은 기준이다
- [ ] 중간 단계 확정은 하단 바 주 동작이고, 확정 뒤 다음 단계로 넘어간다
- [ ] 제목 단계 세 개가 C-19 토큰을 쓰고, 아래 단계가 위 단계보다 크지 않다. 상자 안 상자가 없다 (자동: 화면 실측 검사 P-8)
- [ ] 조회 조건 칸 폭이 좁음, 보통, 넓음 중 하나이고 간격이 같다 (자동: 화면 실측 검사 P-9)
- [ ] 한 화면에 같은 이름의 버튼이 두 곳에 없다 (자동: 화면 실측 검사 P-10)
- [ ] 재사용한 기존 부품을 C-20 표로 점검했다
- [ ] 영어 낱말이 없다(업무 약어 제외). 「남은 일」 조사가 받침에 맞다
- [ ] 입력 칸에 고른 값이 잘리지 않는다 (자동: 화면 실측 검사 P-11)
- [ ] 한 행 안 입력과 버튼의 높이가 같다 (자동: 화면 실측 검사 P-12)
- [ ] 체크박스와 입력의 접근 이름이 화면 안에서 겹치지 않는다 (자동: 화면 실측 검사 P-10)
- [ ] 보이는 문구에 내부 번호(「설비(1)」)가 없다 (자동: 화면 실측 검사 P-13)
- [ ] 소제목은 묶음 위에 있고, 제목과 라벨이 한 줄이다 (자동: 화면 실측 검사 P-14)
- [ ] 처리형: 단계 본문이 1280×800에서 하단 바에 가리지 않는다. 넘치면 자동으로 채워지는 값부터 접었고, 하위 항목 하나의 설정을 여러 단계에 나누지 않았다 (자동: 화면 실측 검사 P-15)
- [ ] 처리형 하위 항목: 저장하면 다음 미완료 항목이 열린다
- [ ] 처리형: 지난 단계 요약이 단계별 묶음과 「라벨 값」 쌍이다. 쉼표, 빗금으로 값을 잇지 않았다
- [ ] 처리 화면에서 저장하지 않은 변경을 두고 떠날 때 확인한다
- [ ] POP, 모바일: 값마다 쓰이는 판단을 말할 수 있다. 목록과 편집 영역 첫 줄은 이름이고 같은 번호를 반복하지 않는다. 목록 줄은 제목 줄(이름, 상태 칩)과 「라벨 값」 정보 영역으로 나뉜다. 수량은 「진행 / 기준」과 막대로 보이고 음수가 없다. 끝난 줄은 「투입 완료」로 보인다. 정상 값은 숨기고 예외만 칩으로 보인다 (C-21)

## 화면 용어집

화면에 보이는 말의 정본이다(C-13). 새 화면에서 같은 뜻을 말할 때 이 표의 말을 쓰고, 없으면 일반 MES 용어를 찾아 더한다.

## 갱신 규칙

- 같은 결정을 두 번째 화면에서 다시 하게 되면 규칙으로 올린다(배치 규범과 같은 기준).
- 규칙을 바꾸면 검사 스크립트의 규칙 번호와 기준 구현을 함께 맞춘다.
- 업무 이슈에 적힌 배치와 구성이 다르면 이 규범이 우선이다(머리말 「근거와 우선순위」). 차이는 그 이슈에 남긴다.
