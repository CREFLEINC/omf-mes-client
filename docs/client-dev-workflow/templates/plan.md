# 작업 계획 양식

```md
## 업무

- 클라이언트 이슈: #<번호>
- 담당 팀: Agent : T<번호>
- 검증 수준: <중요 | 보통 | 낮음>

## 고정된 설계 기준

- 설계 커밋: <전체 커밋>
- 확인 자료: <경로·버전 포인터만>
- 마지막 설계 변동 공지: <없음 | 설계 저장소의 공통 공지 URL 또는 CREFLEINC/omf-mes#번호>

## 목표와 완료 조건

- C-1: ...
- C-2: ...

## 코드 수준 설계

<개발팀이 결정한 구조·변경 범위·구현 순서>

## 작업 단위

<독립적으로 검증하고 되돌릴 수 있는 단위>

## 검증

<선택한 수준과 실제 실행할 명령·수동 확인>

## 요청 또는 개선 제안

<없음 | 정보 요청/설계 개선 문서 경로와 계속 진행할 범위>
```

비공개 설계 본문은 계획서가 공개 저장소에 들어갈 가능성이 있으면 적지 않는다. 로컬 전용 계획서는 `.client-dev/` 아래에 둔다.
