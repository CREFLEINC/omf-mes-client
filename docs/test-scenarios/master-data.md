# 기준정보 사용자 테스트 시나리오

**목적** — 개발이 끝난 화면을 실제로 실행해 사람이 손으로 확인하는 시나리오다. 둘로 쓴다.

1. **자동화**: 브라우저 자동화 Agent가 이 표를 따라 프로그램을 조작하고 「기대 결과」와 실제 화면을 대조한다.
2. **QA 전달**: 품질 담당팀이 같은 표를 손으로 따라 하며 테스트 케이스로 쓴다.

작성 시점 이후 화면이 바뀌면(필드·문구·검증 규칙) 이 문서도 함께 고친다 — 낡은 시나리오는 실제 화면과 다른 것을 「기대 결과」로 남겨 오히려 해가 된다.

> **이 저장소는 공개(public)다.** 아래 테스트 데이터는 전부 지어낸 합성값이며, 화면 슬라이스의 `*.test.ts(x)`가 이미 쓰는 계열(`SYN-`·`SAMPLE-` 등)을 그대로 재사용했다. 실 품목코드·부서코드·거래처코드·고객사명·인프라 정보를 이 문서에 적지 않는다(루트 `CLAUDE.md`).

⚠ **W-06-08(예비품 마스터)·W-06-09(ERP-MES IF 연계정의관리)·W-06-12(MES-ERP 송신IF 정의)는 설계에는 있지만 구현되지 않았다.** 엔드포인트 자체가 없다(프로젝트 기록). W-06-13(검사정책설정)은 W-06-02(검사기준 등록)에 흡수돼 별도 화면이 아니다.

**공유 잠금 메커니즘 — "편집 가능 여부"(editability)** 여러 화면(Routing·검사기준·불량·원인코드·공통코드·품목 확장속성)이 `apps/web/src/patterns/master/editability.ts`의 같은 잠금 판정을 쓴다. 서버가 `editability.reason`으로 코드/마스터 값의 수정 가능 여부를 내려주면 화면은 그 사유에 맞는 문구를 낸다 — 사유는 6가지다.

| 사유 코드 | 안내 문구 |
| --- | --- |
| `REFERENCED` | 「이미 N건에서 사용 중이라 코드를 바꿀 수 없습니다.」(건수를 모르면 "이미 다른 자료에서 사용 중이라…") |
| `NOT_COUNTABLE` | 「이 코드를 참조하는 자료의 수를 확인할 수 없어 코드를 잠급니다. 변경이 필요하면 담당자에게 문의하세요.」 |
| `RECEIVED_FROM_ERP` | 「외부 시스템에서 받은 자료라 여기서 수정할 수 없습니다. 원본 시스템에서 변경하세요.」 |
| `LABEL_ISSUED` | 「이 코드로 발행한 라벨이 현장에 나가 있어 코드를 바꿀 수 없습니다. 변경이 필요하면 담당자에게 문의하세요.」 |
| `SYSTEM_OWNED` | 「이 코드 그룹은 시스템이 관리해 편집할 수 없습니다. 변경이 필요하면 담당자에게 문의하세요.」 |
| `EDITABLE`(잠겼지만 사유 특정 안 됨) | 「지금은 코드를 바꿀 수 없습니다. 변경이 필요하면 담당자에게 문의하세요.」 |

## 실행 환경

| 환경 | 실행 | 기준 URL | 특징 |
| --- | --- | --- | --- |
| 목 서버(Prism) | `pnpm mock` (별도 터미널) | `http://127.0.0.1:4010` | 계약 example을 그대로 돌려준다. **상태가 없다** — 등록·저장 후 목록에 실제로 반영되는지, 낙관적 잠금 충돌(409)은 검증할 수 없다 |
| 관리웹 | `pnpm --filter @omf-mes/web dev` | `http://localhost:5173`(포트 점유 시 5174…) | 기본 API 기준 URL이 목 서버(`127.0.0.1:4010`)다. 실서버로 붙이려면 `VITE_API_BASE_URL=http://localhost:3100/api pnpm --filter @omf-mes/web dev` |
| 실서버(`omf-mes-server`) | `docker compose up -d && pnpm exec prisma migrate deploy && pnpm run db:seed && pnpm start` | `http://localhost:3100/api` | **기준정보(MDM) API만 구현돼 있다** — 이 문서의 화면들은 원래 `/mdm/**`·`/planning/**` 경로를 쓰므로, 다른 도메인 문서보다 실서버 검증 가능성이 높다. 다만 로그인 경로 불일치(아래)가 먼저 풀려야 한다 |

**⚠ 실서버 로그인 경로가 어긋나 있다.** 관리웹 로그인 화면은 `POST /app/sessions`를 부르는데 실서버는 `POST /api/auth/login`을 쓴다. 이 어긋남이 풀리기 전에는 **실서버로는 로그인 화면을 통과할 수 없다** — 이 문서의 모든 시나리오가 실질적으로 목 서버 기준이다.

**「실행 가능 환경」 값의 뜻**

| 값 | 뜻 |
| --- | --- |
| 목 서버 | 화면 진입·조작·입력 검증까지는 확인 가능. 저장 후 상태 반영은 확인 불가(Prism 한계) |
| 목 서버(화면 확인만) | 요청이 나가는 것까지만 확인 가능. 확정·승인·재처리 같은 되돌릴 수 없는 처리의 결과 반영은 실서버 구현 후에만 검증 가능 |

## 알려진 제약 — 시나리오 판정 시 참고

이 문서가 작성된 시점 기준으로 아래는 **결함이 아니라 알려진 상태**다. 자동화 Agent와 QA 모두 이 상태와 실제 화면이 일치하면 「통과」로 판정한다.

1. **실서버는 MDM(기준정보) API만 구현돼 있다.** 이 문서의 화면들은 원래 `/mdm/**`·`/planning/**`을 쓰므로 다른 도메인 문서보다 실서버 적합도가 높지만, 로그인 경로 불일치(`/app/sessions` vs `/api/auth/login`)가 먼저 풀려야 실제로 검증할 수 있다.
2. **W-06-08(예비품 마스터)·W-06-09(ERP-MES IF 연계정의관리)·W-06-12(MES-ERP 송신IF 정의)는 설계에는 있지만 구현되지 않았다.** 엔드포인트 자체가 없다. W-06-13(검사정책설정)은 W-06-02에 흡수돼 별도 화면이 아니다.
3. **W-CO-08(창고 배치도)의 [도면 올리기] 버튼은 항상 비활성이다.** 첨부를 어떤 대상 유형으로 붙일지가 아직 정해지지 않아서다 — 도면 없이 위치만 찍는 것은 정상 동작이다.
4. **W-06-04(판정유형 코드)의 값 목록은 항상 "임시 목록" 안내가 붙는다.** `JUDGMENT_TYPE` 그룹코드 자체는 확정된 실값이지만, 그 안에 어떤 코드값이 있어야 하는지의 목록은 서버(코드값 조회)가 정본이고 화면이 값을 지어내 거르지 않는다.
5. **W-06-06(공통코드·조직·작업자)의 「작업자」 탭은 완전 읽기 전용이다.** 계약에 작업자 자원의 POST·PUT이 없다 — 유일하게 편집 가능한 것은 그 아래 「자격·인증」 구획이다.
6. **W-06-11(마스터 변경관리)은 이 저장소의 첫 읽기 전용 조회 형 화면이라 쓰기 액션이 전혀 없다.** 상단 [신규 개정 발행] 버튼은 감추지 않고 항상 보이지만 늘 비활성이다 — 개정 발행은 각 마스터 화면(Routing·검사기준 등)의 몫이다.
7. **여러 화면의 필터 선택지가 "조회한 결과에서 뽑은 임시 목록"이다**(W-06-10 연계 동기화 현황의 상태·인터페이스·방향·대상 종류, W-06-11의 대상 종류·사건 종류). 값 목록 자체가 서버에 코드로 확정돼 있지 않아, 한 번도 기록되지 않았거나 지금 조회 기간 밖의 값은 선택지에 없다 — 조회를 막지는 않는다.
8. **목 서버(Prism)는 상태가 없다.** 저장·확정·승인·재처리 뒤 목록에 실제로 반영되는지, 낙관적 잠금 충돌(409)은 목 서버로 검증할 수 없다 — 이 문서에서 「(목 서버 한계) 요청 전송만 확인」이라 적은 스텝이 이에 해당하며, 실서버가 준비되면 그 스텝을 결과 확인까지 확장한다.
9. **베트남어 i18n은 실제로 없다** — `vi.ts`가 한국어를 그대로 재수출하는 자리표시자다. 다국어 표시 검증은 이번 범위에서 뺀다.
10. **이 도메인에는 모바일·POP 화면이 없다.** 기준정보는 사무 업무라 현장 단말 화면이 배정돼 있지 않다 — 빠뜨린 것이 아니다.
