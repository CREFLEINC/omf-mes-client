# 빠른 시작 — 입하부터 출하까지

자재가 공장에 들어와 제품이 되어 나가기까지의 **전체 흐름**을 따라가며, 각 구간에서 단말로 무엇을 하는지 설명합니다.

처음 사용하는 경우 이 문서만 읽어도 됩니다. 화면을 하나씩 자세히 확인해야 할 때만 아래 링크를 따라가세요.

## 전체 흐름

| 단계                                                       | 업무                                    | 단말의 역할 |
| ---------------------------------------------------------- | --------------------------------------- | ----------- |
| 1 · [자재 입하](#1단계--자재-입하-및-보관)    | 공급사 자재 입고 및 보관 위치 적재     | **큼**      |
| 2 · [생산 준비](#2단계--생산-계획-준비)              | 생산 품목 · 시기 · 수량 결정        | 거의 없음   |
| 3 · [생산 실행](#3단계--생산-실행)                     | 자재 투입 및 생산               | **큼**      |
| 4 · [제품 출하](#4단계--제품-출하)                    | 완제품 입고 후 출하   | **큼**      |

**단말이 모든 작업을 처리하지는 않습니다.** 계획을 세우고 판정을 내리는 일은 관리웹에서, 생산 실적은 현장 POP에서 처리합니다. 이 문서는 **그 사이에서 단말이 담당하는 부분**을 설명합니다.

---

## 시작 전 준비 사항

**1. 사번이 내 사번인지 확인합니다.** 화면 맨 위에 표시됩니다.

![화면 맨 윗줄. 왼쪽에 화면 이름, 가운데에 홍길동 · 100027, 오른쪽에 초록색 온라인 표시](images/공통-08-머리말.png)

여기에 표시된 사번으로 기록이 남습니다. 다른 사람의 사번이라면 **작업 목록에서 뒤로가기를 한 번 눌러** 사번 확인 화면으로 이동해 변경하세요.

**2. 온라인 상태인지 확인합니다.** 오른쪽 표시가 `오프라인`이면 수행할 수 없는 작업이 있습니다. → [연결 단절](예외-상황.md#연결-단절)

나머지 조작법(스캔·직접 입력·수량 입력)은 [공통 조작 방법](README.md#공통-조작-방법)에 있습니다.

## 1단계 · 자재 입하 및 보관

공급사 차량이 도착했습니다. **자재 입고부터 보관 위치 적재까지**가 이 단계입니다.

### 순서

**① 받은 내용을 기록합니다** — [입하 등록](01-자재창고.md#입하-등록)

자재 LOT 라벨을 스캔하고, 어느 발주 건인지 선택한 뒤, 실제로 받은 수량을 입력합니다.

![입하 등록 첫 화면. 자재 LOT 라벨을 스캔하세요라는 빨간 테두리 입력란, 직접 입력 버튼, LOT 번호 없음 버튼](images/01-입하등록-1-스캔.png)

이 화면에서 **입하 기록과 자재 LOT이 한 번에 생성됩니다.** 라벨이 붙어 있던 자재는 LOT도 함께 생성됩니다.

**② 보관 위치에 넣습니다** — [적치·입고 완료](01-자재창고.md#적치입고-완료)

받은 자재는 아직 하역장에 있습니다. 내 사번으로 배정된 적치 지시를 선택하고, **보관 위치를 먼저 스캔한 뒤 자재를 스캔**하여 등록합니다.

![적치 지시를 고른 뒤. 권장 위치와 같습니다라는 초록 안내와 ① 적치 위치 ② 자재 LOT 스캔 두 단계](images/07-적치-3-LOT확인.png)

**여기까지 완료해야 해당 자재가 재고로 반영됩니다.** 적치를 마치지 않으면 다음 작업자가 그 자재를 찾지 못합니다.

### 자주 발생하는 상황

| 상황                                    | 조치                                                                                                        |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 라벨이 훼손되어 스캐너가 읽지 못할 때   | 화면의 **직접 입력**으로 번호를 입력합니다                                                                  |
| 라벨이 붙어 있지 않을 때                | 입하 등록에서 **LOT 번호 없음** → 나중에 [자재LOT 스캔·등록](01-자재창고.md#자재lot-스캔등록)으로 채웁니다 |
| 받은 수량이 예정과 다를 때              | 화면이 정량분과 초과분을 구분합니다 → [수량 불일치](예외-상황.md#수량-불일치)                |
| 지정된 보관 위치가 가득 찼거나 넣을 수 없을 때 | [임시 위치 적재](01-자재창고.md#임시-위치-적재)로 넘어갑니다                                          |
| 검사를 기다릴 수 없을 때                | [긴급 IQC 생략 요청](01-자재창고.md#긴급-iqc-생략-요청) — **승인을 받아야 사용할 수 있습니다**              |

### 단말 외 처리 업무

- **검사 대상 여부**는 등록한 뒤에 줄마다 정해집니다. 단말이 정하지 않습니다.
- 받은 자재는 대부분 **보류 상태**로 들어옵니다. 품질 부서에서 해제해야 사용할 수 있습니다.
- 반품할지 폐기할지는 오류를 기록하면 담당자가 관리웹에서 판단합니다.

## 2단계 · 생산 계획 준비

무엇을 언제 얼마나 만들지 정하는 단계입니다. **관리웹에서 처리합니다** — `W/O 확정·배포·생산LOT 선발행` 화면입니다.

### 단말의 역할

거의 없습니다. 다만 계획을 준비하는 담당자가 창고에 확인을 요청할 때 아래 두 화면을 사용합니다.

**필요한 자재가 지금 어디에 얼마나 있는지 확인** — [자재 위치 확인](01-자재창고.md#자재-위치-확인)

라벨을 읽으면 그 자재가 있는 위치와 수량이 표시됩니다. **아무것도 기록되지 않는 화면**이므로 여러 번 조회해도 문제가 없습니다.

![자재 위치 확인 결과. 위치 2곳이라는 안내 아래 창고와 위치별로 보유·가용·예약 수량이 카드로 나열되어 있다](images/06-자재위치-2-결과.png)

**자재를 생산에 가까운 창고로 옮기기** — [재고 이동](01-자재창고.md#재고-이동)

반출과 도착을 **두 번에 나누어** 처리합니다. 물건을 옮기는 시간이 그 사이에 있습니다.

### 이 단계 완료 후

생산에 필요한 자재를 꺼내 달라는 **자재 출고요청**이 생성됩니다. 이것이 창고 단말에 **피킹 지시**로 표시됩니다 — 다음 단계입니다.

---

## 3단계 · 생산 실행

계획대로 자재를 라인에 넣고 만드는 단계입니다. 창고와 현장 **양쪽에서** 단말을 사용합니다.

### 창고 — 자재 출고

**[자재 출고·피킹](01-자재창고.md#자재-출고피킹)**

내 사번으로 배정된 피킹 지시를 열면 집을 줄 목록이 표시됩니다. 줄마다 **어느 위치에서 어느 LOT을 얼마나** 집을지 적혀 있습니다.

![피킹 라인 목록. 각 줄에 품목, 선출 순위, 요청과 피킹 수량, LOT 번호, 위치가 적혀 있다](images/09-자재출고-2-피킹라인.png)

줄마다 집은 뒤, 모두 집었으면 **출고 확정**을 한 번 누릅니다.

### 현장 — 자재 인수 및 투입

**[생산창고 입고](01-자재창고.md#생산창고-입고)**

창고에서 온 출고 전표를 스캔하고 **실제로 받은 수량**을 입력합니다. **호퍼에 남은 수량**도 같은 화면에서 입력합니다.

![출고 전표를 읽은 뒤. 라인 수령 아래 두 줄의 수령 수량 입력란과 그 아래 호퍼 잔량 부분](images/10-생산창고입고-2-확인.png)

### 생산 중 — POP과 단말의 역할 분담

| 작업                      | 처리하는 곳                                            |
| ------------------------- | ------------------------------------------------------ |
| 생산 수량 기록            | **현장 POP** — `생산 실적 등록` 화면                   |
| 다음 공정으로 이동        | 단말 — [WIP 공정 이동](02-생산이동.md#wip-공정-이동)   |
| 불량품 수리 투입·반출     | 단말 — [수리 왕복 스캔](02-생산이동.md#수리-왕복-스캔) |
| 설비 점검                 | 단말 — [설비 점검](05-설비.md#설비-점검)               |
| 설비 정지 보고            | 단말 — [설비 고장 보고](05-설비.md#설비-고장-보고)     |

**WIP 공정 이동과 수리 왕복 스캔은 연결이 있어야 합니다.** 연결이 끊긴 상태에서는 화면이 열리지 않습니다.

### 자주 발생하는 상황

| 상황                          | 조치                                                                     |
| ----------------------------- | ------------------------------------------------------------------------ |
| 집을 LOT이 보류 상태일 때     | 집을 수 없습니다. 화면에 사유와 해제 조건이 함께 표시됩니다              |
| 요청보다 적게 집었을 때       | 그대로 확정하면 부족분이 남습니다. 대체 자재는 이 화면에서 처리하지 않습니다 |
| 받은 수량이 출고량보다 적을 때 | 차이 사유를 반드시 선택하세요                                            |
| 설비가 멈췄을 때              | **발견 즉시** 고장 보고. 세 항목만 입력합니다                       |

## 4단계 · 제품 출하

만든 제품을 완제품 창고에서 받아 보관하고, 출하일에 집어 출고하는 단계입니다.

### 순서

**① 만든 제품을 받아 보관 위치에 넣습니다** — [제품 입고·적치](04-출하.md#제품-입고적치)

제품이 담긴 **인식표**를 스캔하고 실제 수량을 입력한 뒤, 적치 위치를 스캔합니다.

![인식표를 읽은 뒤 화면. 인수 대상 줄마다 실물 수량과 인식표 수량, 그 아래 적치 위치와 권장 위치](images/15-제품입고-2-인식표.png)

**이 화면에서 받지 않으면 그 제품은 출하 흐름에 들어오지 않습니다.** 이후의 피킹·검사·출하가 모두 이 화면에서 받은 기록을 기준으로 합니다.

**② 출하할 제품을 집습니다** — [제품 피킹](04-출하.md#제품-피킹)

오늘 출하할 줄을 선택하면 고객이 지정한 조건과 집을 수 있는 LOT이 순서대로 표시됩니다.

![제품 피킹. 피킹 대상 카드와 고객 LOT 요구, 그 아래 권장 LOT 목록이 카드로 나열되어 있다](images/16-제품피킹-2-권장LOT.png)

**고객 LOT 요구는 자유 문장으로 들어옵니다.** 화면이 내용을 해석하지 않으므로 읽고 직접 판단하세요.

**③ 필요하면 포장을 바꿉니다** — [포장 재구성](04-출하.md#포장-재구성)

합치거나 나누거나 내용을 변경합니다. **되돌릴 수 없습니다.**

### 단말 외 처리 업무

실제로 차량에 싣고 출하를 확정하는 것은 **관리웹**에서 처리합니다 — `출하 예정 목록`, `출하 처리(상차·실물 출고)`, `출하 확정·취소` 화면입니다. 단말의 역할은 **집는 단계까지**입니다.

라벨 출력도 단말에서 하지 않습니다 — **POP**에서 처리합니다.

## 작업 종료 후

- 전송하지 못한 기록이 남아 있으면 화면 위에 `전송 대기 N`이 표시됩니다. **연결되면 자동으로 전송됩니다.**
- `전송 실패 N`이 표시되었다면 기다려도 전송되지 않습니다. → [전송 실패한 기록](공통-화면.md#전송-실패한-기록)
- 교대 시에는 **작업 목록에서 뒤로가기를 한 번 눌러** 사번을 변경합니다.
