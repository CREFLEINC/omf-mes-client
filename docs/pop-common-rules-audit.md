# POP 공통 밀도·선택 팝업 적용 기록

- 기준 설계: `omf-mes` 고정 커밋 `5b3d77376534694fb5b2d1e384bc35745d91b270`
- 기준 조항: `design/wiki/decisions-policy/공유계약.md` E-1·E-3·G-34
- 점검 화면: `apps/web/src/routes/pop.tsx`의 공개 라우트 21개

## 공통 적용

- 모든 공개 화면 루트는 `.pop-ui`를 사용한다. `lg`·`xl`·`2xl` 컨트롤 높이는 이 겹에서
  관리웹 기본 `md` 토큰으로 수렴한다. 폐기된 56·64·72px 하한은 사용하지 않는다.
- 선택형 입력은 `PopSelect`로 통일한다. 닫힌 상태에 현재 값과 `[선택]`을 분리해 보이고,
  팝업 안에서 이미 받은 후보만 로컬 검색한다. 목록 내부 스크롤, 검색어 지우기,
  `[페이지 위]`·`[페이지 아래]`, 현재 페이지와 전체 건수를 제공한다.
- G-34의 공통 `[화면 이동]`은 이번 변경에서 제외한다. 현재 클라이언트에는 작업자·단말별
  접근 가능 화면 목록의 정본이 없으며, 공개 라우트 전체를 후보로 쓰면 권한 밖 화면을
  노출할 수 있다. 특히 `P-CO-01`에서는 작업자 지정 전에 다른 화면으로 이동할 수 있는
  내비게이션과 관련 dataset을 렌더하지 않는다.
- 기존 사번 해제 동작은 문구를 `[사용자 전환]`으로 맞췄다. 현재 활성 사번만 지우고
  `P-CO-01`로 이동하며 저장 기록·오프라인 큐는 수정하지 않는다.

## 경계

- API 클라이언트, 요청 본문, 호출 순서, 쿼리 키는 변경하지 않는다.
- 서버 페이지네이션 후보는 화면이 이미 받은 범위만 `PopSelect`에 전달되므로 그 범위만
  검색한다. 추가 페이지를 검색하기 위한 API 호출은 만들지 않는다.
- 작업자·단말별 접근 가능 화면 목록이 확정되기 전까지 배포 셸에 공통 화면 이동을 넣지 않는다.
  공개 라우트 목록이나 화면별 403 응답은 내비게이션 후보의 안전한 정본이 아니다.
