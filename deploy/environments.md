# 배포 환경

지금 관리웹이 돌고 있는 서버들의 **실제 값**이다. 절차와 함정은 [README](./README.md)에 있고 이 문서는 값만 적는다. 값이 바뀌면 여기부터 고친다.

> 계정 비밀번호·토큰·레지스트리 자격은 **여기 적지 않는다.** 이미지는 공개 pull 대상이라 서버에 자격이 필요 없고, push용 자격은 GitHub Actions secret에만 둔다.

| ------------------------ | ----------------------------- | ------------------------------------- |
| 접속                     | `ssh github-runner`           | `ssh omf-sjvina`                      |
| 호스트명                 | `captain-System-Product-Name` | `mes-server`                          |
| 배포 디렉터리            | `/opt/services/omf-mes-front` | `/opt/services/omf-mes-front`         |
| 바인딩 IP                | `192.168.1.72`                | `192.30.0.189`                        |
| 공개 포트                | **3180**                      | **80**                                |
| API 원점(`API_UPSTREAM`) | `http://mesapi.crefle.ai`     | `http://192.30.0.189:9000`            |
| 사용자가 접속하는 주소   | `http://mes.crefle.ai`        | `http://117.4.237.67/`                |
| 백엔드 위치              | 같은 호스트 `3100`            | 같은 호스트 `9000`(→ 컨테이너 `3100`) |

**두 칸이 서로 다른 것에 주의한다** — 「사용자가 접속하는 주소」와 「API 원점」은 방향이 반대다. 앞엣것은 브라우저가 들어오는 문이고 뒤엣것은 관리웹 컨테이너가 나가는 문이다. 고객사에서 이 둘을 같게 뒀다가 `/api`가 전부 504였다(아래 참고).

## 테스트 서버

- 사내 공용 박스라 **포트가 빽빽하다.** 이미 물린 포트: 22 · 80(eq0-dashboard) · 3000(inventory-web) · 3100(omf-mes-api) · 3306 · 8000 · 8001 · **8080(Harbor)** · 8090(omf-dx-web) · 8888 · 20051. 설치 스크립트 기본값 8080을 쓸 수 없어 3180을 쓴다. 새 포트는 `ss -lnt`로 먼저 본다.
- 도메인은 **`.ai`** 다(`mes.crefle.ai` · `mesapi.crefle.ai`). 둘 다 별도 reverse proxy가 받아 넘긴다 — 이 서버에서 프록시 설정을 손댈 일은 없다. `*.crefle.com` 쪽에 `mesapi` 레코드는 **없다**(NXDOMAIN). 「`.com`이다」라는 말을 들어도 실측부터 한다.
- 앞단 프록시를 못 믿을 상황이면 `http://192.168.1.72:3100` 직결이 우회다.
- 이 서버는 GitHub Actions self-hosted runner도 겸한다(이미지 빌드가 여기서 돈다).

## 고객사 서버 (SJ Vina)

- 2026-09-17 추가. Ubuntu 26.04 · 12 vCPU · 30GB RAM · 디스크 856GB 여유 · 시간대 `Etc/UTC`.
- 계정 `omfadmin`은 docker 그룹 소속이라 `sudo` 없이 도커를 쓴다. `sudo`는 비밀번호를 물어 `ufw` 확인은 막힌다.
- **`117.4.237.67`은 이 서버의 공인 IP**다. 브라우저는 이 주소로 들어오지만, **서버가 나갈 때 이 주소를 쓰면 안 된다** — 자기 자신에게 되돌아와야 해서(헤어핀 NAT) 닿지 않는다. 첫 설치에서 `--api-upstream`에 이 주소를 넣었다가 `/api`가 전부 504였고, LAN 주소로 바꿔 풀었다.

  | 컨테이너 안에서 `/api/health` |           |
  | ----------------------------- | --------- |
  | `http://117.4.237.67:9000`    | 도달 실패 |
  | `http://192.30.0.189:9000`    | **200**   |

- 공인 IP는 **출발지 허용 목록 방화벽** 뒤에 있다. 사무실 밖(클라우드·개인 PC)에서는 닿지 않으므로 **도달 확인은 서버 안에서** 한다. 「내 PC에서 안 된다」는 고장의 증거가 아니다.
- 백엔드도 같은 서버에 있다 — `omf-mes-proxy-1`(`9000` → `omf-mes-api-green-1:3100`) · `omf-mes-postgres-1`. 배포 위치는 `/opt/services/omf-mes-server`(서버 저장소 소관).
