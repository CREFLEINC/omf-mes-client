# 위험도 분류 — 이 저장소 적용

정본은 `operating-policy.md` §6.2다. 이 문서는 그 기준을 이 저장소의 실제 작업에 대응시킨 판정 보조 자료다. 조건 자체를 바꾸지 않는다.

## 판정 순서

1. 아래 **높은 위험 목록**에 하나라도 해당하는가 → 높음
2. **낮은 위험 4조건을 전부** 만족하는가 → 낮음
3. 둘 다 아니면 → 중간
4. **판단이 갈리면 더 높은 쪽을 적용한다** (§6.2 말미)

낮은 위험 4조건: ① 변경 범위가 작고 국소적 ② 공개 인터페이스·사용자 흐름 불변 ③ 데이터 복구·운영 중단·외부 협업 없이 되돌릴 수 있음 ④ 보안·권한·개인정보·데이터 구조에 영향 없음.

## 이 저장소의 사례 대응

| 작업 | 위험도 | 근거 |
| --- | :-: | --- |
| 화면 문구·i18n 라벨 수정 | 낮음 | 국소적·되돌리기 쉬움 |
| 기존 화면 슬라이스 내부 리팩터링(외부 props 불변) | 낮음 | 경계 밖 영향 없음 |
| 테스트 추가(구현 변경 없음) | 낮음 | |
| 화면 1장 신규 구현(패턴·계약 기존 것 사용) | 중간 | 여러 파일·한 사용자 흐름 |
| `patterns/` 공통 workflow 추가·변경 | **높음** | 광범위한 공통 컴포넌트 변경 — 여러 화면이 소비 |
| `packages/api-client`·`domain`의 공개 export 변경 | **높음** | 공개 인터페이스 변경 |

| `pnpm gen:api` 재생성으로 계약 타입이 바뀌는 경우 | **높음** | 데이터 계약 변경 |
| 허용 의존 규칙(`.dependency-cruiser.cjs`)·워크스페이스 구성 변경 | **높음** | 빌드·검증 파이프라인 변경 |
| `tools/mock` 도구 교체(Prism → 상태 기반 Mock) | **높음** | 개발 파이프라인 변경 |
| 화면 슬라이스 신설이 patterns·packages를 함께 건드릴 때 | **높음** | 여러 핵심 흐름 동시 영향 |

## 이 저장소 고유의 중단 조건

정책 §14의 중단 조건에 더해, **이 저장소가 공개(public)**이므로 다음은 즉시 중단하고 사용자에게 보고한다. 근거: 루트 `CLAUDE.md`.

- 비공개 설계 저장소(omf-mes) 문서의 **본문을 코드·주석·커밋 메시지·PR 본문·테스트 픽스처에 옮겨야** 할 때 → 이슈 번호만 참조하는 방식으로 대체 가능한지 먼저 확인한다
- 고객사 식별 정보·계약 정보·실 운영 값(실제 사번·품목코드·LOT 번호·거래처 코드)·인프라 정보(IP·호스트명·계정)가 산출물에 들어가야 할 때 → 합성값으로 대체한다
- 계약 정본(OpenAPI)을 이 저장소로 **복사**해야 한다는 판단이 설 때 → 참조 방식이 정본 규칙이다

이미 공개된 것을 발견하면 조용히 되돌리지 않고 즉시 보고한다(force push·history 재작성 금지).

## 승인 절차

| 위험도 | 계획 형식 | 승인 |
| :-: | --- | --- |
| 낮음 | `assets/plan-template.md`의 간략 계획 | 보고 후 대기 없이 실행 |
| 중간 | 상세 계획 전 항목 | **사용자 승인 후 실행** |
| 높음 | 상세 계획 + 대안·영향·복구 방법 | **사용자의 명시적 승인 후 실행** |

사용자가 모든 작업에 사전 승인을 요구한 경우에는 위험도와 무관하게 승인을 기다린다.
