# 전례 슬라이스 사본 체크리스트 (v1.1 신설)

화면 슬라이스는 서로 import하지 않고 전례를 **사본 소유**한다. 이 방식의 알려진 실패 형태는 「전례의 인자·감지기를 반쪽만 베끼는」 것이다 — 최근 리뷰 Major의 다수가 이 형태였다. 이 목록은 그 실측 결함들을 항목화한 것이다.

**사용법**: 전례 슬라이스를 베껴 새 화면을 시작할 때 **구현 담당이 착수 시 대조**하고, 항목별 체크 결과(해당 없음 포함)를 **실행 보고서에 적는다**. 오케스트레이터는 implementer 프롬프트에 이 대조를 포함한다(SKILL.md 7~8절).

각 항목의 괄호 표기는 근거가 된 발견 회차·이슈의 **출처 표식**이다. 회차 보고서는 `.gitignore`된 로컬 산출물이라 공개 저장소 독자는 따라갈 수 없다 — 그래서 각 결함 설명은 표식 없이도 자립적으로 이해되게 썼다. 항목을 추가할 때도 같은 원칙을 지키고, **결함 서술은 컴포넌트·규칙의 언어로만** 쓴다(공개 저장소 경계 — 루트 `CLAUDE.md`).

## 체크리스트

- [ ] **404 정리 `setSearchParams`의 `{ replace: true }` + 히스토리 한 칸 감지기** — 인자를 잃으면 없는 항목 주소를 지우는 정리가 히스토리에 칸을 쌓아, 뒤로가기가 없는 항목 주소로 되돌아가 같은 정리가 되풀이되고 사용자가 갇힌다. 전례는 인자와 「정리가 뒤로가기 기록을 늘리지 않는다」 감지기를 함께 두었다. (W-01-06 PR ② 리뷰 Major ①)

- [ ] **표의 `getRowId` + 「앞 줄이 사라져도 포커스가 남는다」 감지기** — 미지정이면 인덱스가 React key가 되어, 앞 줄이 사라질 때 치고 있던 칸의 DOM 노드가 대신 지워지고 입력·포커스가 말없이 다른 줄로 옮겨 붙는다. (W-01-06 PR ② 리뷰 Major ②)

- [ ] **줄 단위 사유/오류 `id` 격리(`ordinal`) + 감지기** — 줄 번호가 `id`에 들어가지 않으면 잠긴 줄이 둘일 때 두 줄의 칸이 같은 `id`를 공유해, 라벨·오류 연결이 남의 줄을 가리킨다. 감지기는 「잠긴 줄이 둘이면 각 줄의 칸이 자기 줄의 사유를 가리킨다」. (W-01-06 PR ② 리뷰 Major ②)

- [ ] **`resetIfIdle` 규율 — `reset()` 호출 자리 전부 경유 + 나가는 중 깃발** — 쓰기 훅의 `reset()` 직접 호출은 나가는 중인 요청의 되먹임(성공·실패 후처리)을 끊는다. 호출부는 전부 `resetIfIdle`를 경유하고 진행 중 깃발을 본다. (#96 · W-01-06 PR ④ 리뷰 Major)

- [ ] **확인 창: `closeOnBackdropClick={false}` · `showCloseButton={false}` · Escape 「닫혀도 무너지지 않게」 + 각 감지기** — 스크림 클릭·X로 창이 새면 진행 중 쓰기와 창의 수명이 어긋나고, Escape로 닫힌 뒤 재조회가 오면 상태가 무너진다. 세 방어와 각각의 감지기를 전례에서 함께 가져온다. (전례 규율 — W-01-06 PR ④ 리뷰 대조 항목)

- [ ] **NBSP 상수는 escape 표기(`' '`) + `codePointAt` 단언 + export(자기참조 금지)** — 원시 U+00A0 글자로 적으면 「비가시 공백 정리」 도구가 보통 공백으로 바꿔도 아무 감지기도 울리지 않는다. 시험의 기대값이 상수 자기참조면 함께 바뀌어 역시 침묵한다 — escape 표기와 코드포인트 단언 두 겹으로 막는다. (#107 · W-01-06 PR ③ 리뷰 Minor ③)

- [ ] **쓰지 않는 prop·export는 정의째 제거(값만 지우지 않는다)** — 값만 안 넘기고 prop 정의를 남기면 「이 슬라이스에 그 기능이 없다」가 타입 수준의 사실이 되지 못하고, 죽은 통로가 다음 사본으로 전파된다. (W-01-06 PR ① 리뷰 — 모범 사례로 확인된 규율)

- [ ] **열 폭 잣대는 선언(상수)과 산출물(`<col>`) 두 자리** — 한 자리만 재면 폭 상수와 실제 렌더 산출물이 어긋나도 잡히지 않는다. 전례의 폭 감지기는 선언과 산출물을 각각 잰다. (W-01-06 PR ① 리뷰 대조 항목)

- [ ] **음성 단언은 짝 양성과 같은 시점(`waitFor`/`findBy` 뒤)** — 렌더가 완료되기 전에 「없다」를 재면 아직 아무것도 없는 화면에서 항상 통과하는 무의미한 단언이 된다. 짝이 되는 양성 단언이 잡은 시점 뒤에 잰다. (전례 테스트 전반의 작성 규율 성문화 — 특정 발견 회차 없음)

- [ ] **참조 조회는 좁히지 않는다 — 선택지만 좁히고 이름 풀이는 전체** — 화면의 선택 목록을 좁힌 조회를 이름 풀이에도 쓰면, 좁힘 밖의 정상 자료가 「알 수 없음」으로 보인다. 좁힘은 선택지 한 자리에만 건다. (#47 · W-01-06 PR ① 리뷰 대조 항목)

- [ ] **전례의 두 스텁 형태(헤더만 바뀌는/내용까지 바뀌는 재조회)를 둘 다 가져온다** — 재조회 스텁이 같은 구조를 되돌리면(구조 공유) 「값이 바뀌었다」를 재는 감지기가 부분 견줌으로 헛통과한다. 호출 횟수에 따라 내용까지 달라지는 스텁이 있어야 갱신 경로의 감지기가 실제로 문다. (#43 방법론의 심화 — W-01-06 PR ② 감지기 수선에서 실측)

## 항목 추가 기준

새 화면의 리뷰·검증에서 「전례에는 있는데 사본에서 빠진」 형태의 결함이 나오면, 같은 형식(항목 + 자립적 결함 설명 + 출처 표식)으로 이 목록에 추가한다. 목록이 길어지는 것보다 같은 결함이 세 번째 화면에서 반복되는 것이 비싸다.
