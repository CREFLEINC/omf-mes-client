# 이슈 종료 정리보고 양식 (v1.1 신설)

오케스트레이터가 GitHub 이슈를 닫으며 정리보고를 할 때 이 양식을 따른다. 정책 §11~§12의 실행·검증 보고서를 **대체하지 않는다** — 이슈 종료 시점의 추가 산출물이다.

```markdown
# 정리보고 — <이슈 번호 · 제목>

## 1. 요약

<어떤 작업을 어떤 목표로 진행해 결과가 어떻게 됐는지 — 핵심만 명확히. 3~5문장.>

## 2. 진행 작업 설명

<GitHub 이슈가 대상이면 이슈 내용 정리 — 요구사항과 범위. 대상 화면·컴포넌트는 내부 식별자로 적는다.>

## 3. 계획 구성

<진행 절차와 작업 단위 구성 — 서술형으로 길게 쓰지 않고 요약한다. 특히 **어떻게 분할했는지**: 계획서의 작업 단위 표를 압축해 옮긴다.>

| 작업 단위 | 목적 | 분할 근거 |
| --------- | ---- | --------- |
|           |      |           |

## 4. 팀 구성

| 역할 | subagent_type | 호출/재개 방식 | 병렬 여부 |
| ---- | ------------- | -------------- | --------- |
|      |               |                |           |

## 5. Agent별 업무 프로파일링

<합계 소요는 경과 시간과 다르다 — 병렬 구간을 표기한다.>

| Agent | 소요(시작~종료) | 병렬 구간 | 회차 수 | 검증 반환 건수 | 리뷰 지적(B/M/m/N) | 범위 밖 변경 | 재확인 통과 | 교차 포착 |
| ----- | --------------- | --------- | ------- | -------------- | ------------------- | ------------ | ----------- | --------- |
|       |                 |           |         |                |                     |              |             |           |
```

### 작성 시 유의

- **규모 비례** — 화면급·다중 Agent 작업은 5절 전체를 쓴다. 단일 Agent 소형 작업(낮은 위험)은 1~2절만 쓰고 3~5절은 「해당 없음」 한 줄로 접는다. 보고가 작업보다 커지면 안 된다.
- **5절은 지표 표만 쓴다 — 자유 서술 평가 금지.** 서술형 평가는 반복되면 상투 문구로 퇴화하고, 오케스트레이터에게는 검증 담당을 주관 평가할 독립 근거가 없다. 표의 지표는 전부 회차 파일명(`_r2`·`_r3`)과 보고서 판정에 이미 있는 값이다 — **새 조사를 만들지 않는다**.
- **교차 포착**은 검증·리뷰가 서로 놓친 것을 상대가 잡은 건수다 — 검증자 정확도의 유일한 관찰 가능 신호이므로 0이어도 적는다.
- **리뷰 지적(B/M/m/N)** 은 심각도별 건수다 — Blocker / Major / Minor / Nit (예: `0/1/3/2`).
- **시간의 출처**: 각 보고서(실행·검증·리뷰)의 시작·종료 시각 필드와, 오케스트레이터가 기록한 Agent 호출·반환 시각. 사후 재구성하지 않는다.
- **공개 경계** — 이슈 종료 코멘트는 공개 저장소에 실린다. 비공개 설계 문서 본문·고객 정보를 옮기지 않고, 결함·계획 서술은 컴포넌트·규칙의 언어로만 쓴다(루트 `CLAUDE.md`). Agent 프로파일링 수치 자체는 공개해도 무방하다.
