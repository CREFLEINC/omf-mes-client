# 실행 보고서 양식

운영 정책 §11의 양식이다. 실행 담당 Agent가 작성한다.

```markdown
# 실행 보고

작업 시작·종료 시각: <YYYY-MM-DD HH:MM ~ HH:MM>

## 변경 내용

## 변경 파일

## 구현 중 주요 판단

## 변경 전 기준 상태

| 검증 항목 | 실행 방법 | 결과 또는 기존 실패 |
| --------- | --------- | ------------------- |
|           |           |                     |

## 추가한 테스트 또는 검증 수단

## 자체 검증 결과

| 검증 항목 | 실행 방법 | 결과 |
| --------- | --------- | ---- |
|           |           |      |

## 남은 위험 또는 확인 필요 사항
```

### 작성 시 유의

- **「변경 전 기준 상태」는 변경을 시작하기 전에 기록**한다. 나중에 채우면 기존 실패와 신규 실패를 구분할 근거가 사라진다.
- 「실행 방법」에는 실제로 실행한 명령을 그대로 적는다(예: `pnpm --filter @omf-mes/api-client test`).
- 「결과」에는 통과/실패와 함께 판단 근거가 되는 출력 요약을 적는다. 실행하지 않은 검증을 통과로 적지 않는다.
- 계획에 없던 변경이 필요해졌다면 실행하지 말고 중단해 보고한다(정책 §6.4·§14).
- 비밀정보·개인정보·고객사 식별 정보는 보고서에 넣지 않는다.
- **시작·종료 시각은 회차마다 적는다**(v1.1) — 이슈 종료 정리보고(`closing-report-template.md`)의 프로파일링 근거다. 사후 재구성하지 않는다.
