# 검증 보고서 양식

운영 정책 §12의 양식이다. 검증 담당 Agent가 작성한다.

```markdown
# 독립 검증 보고

작업 시작·종료 시각: <YYYY-MM-DD HH:MM ~ HH:MM>

## 검증 대상

## 계획 범위 준수 여부

## 변경 전 기준 상태 확인

## 완료 조건별 결과

| 완료 조건 | 검증 방법 | 결과 | 증거 또는 비고 |
| --------- | --------- | ---- | -------------- |
|           |           |      |                |

## 회귀 검증 결과

## 발견된 문제

## 기존 실패와 신규 실패의 구분

## 추가로 수행한 검증

## 최종 판정

- [ ] 통과
- [ ] 작업 결과 통과, 기존 실패 존재
- [ ] 수정 후 재검증 필요
- [ ] 검증 불가 및 사용자 판단 필요
```

### 작성 시 유의

- **배정된 검증을 직접 실행**한다. 실행 담당의 자체 검증 결과나 설명을 증거로 대신 쓰지 않는다(정책 §7.1).
- 「증거」에는 실행한 명령과 결과의 핵심 출력을 적는다. 파일이 존재한다는 사실만으로 통과 판정하지 않는다.
- 「발견된 문제」에는 **재현 방법과 기대 결과**를 함께 적는다. 실행 담당이 그대로 재현할 수 있어야 한다.
- 문제를 직접 수정하지 않는다. 실행 담당 Agent에게 반환한다.
- 계획 범위 밖 변경이 있으면 `git status`·`git diff --stat` 결과를 근거로 적는다.
- 추가 검증에 배포·외부 전송·외부 데이터 변경·비용이 필요하면 실행 전에 사용자 승인을 받는다(정책 §7.3).
- 판정은 하나만 고른다. 이번 변경으로 실패한 항목이 있거나 계획된 검증을 수행하지 못했다면 「통과」로 적지 않는다.
- **시작·종료 시각은 회차마다 적는다**(v1.1) — 이슈 종료 정리보고(`closing-report-template.md`)의 프로파일링 근거다. 사후 재구성하지 않는다.
